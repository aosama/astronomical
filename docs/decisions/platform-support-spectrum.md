# Decision record: macOS support spectrum and the baseline/booster contract

- Status: proposed — accepted on merge (2026-09-05)
- Origin: repository issue #406 — "Align M-series and macOS spectrum support with baseline correctness and probe-gated boosters"

> Deployment note: the pins below apply to future builds. The current Stable release (0.2.29) still requires macOS 26; public copy states this transition explicitly, and the downloadable floor changes when the next Stable cut regenerates the Sparkle appcast with the 14.0 floor.

## Decision

Astronomical supports **any Apple Silicon M-series Mac running macOS 14.0 (Sonoma) or later**,
declared **best-effort**:

1. Baseline correctness and declared model precision hold on every macOS 14.0+ × M-series
   combination. This is protected by architecture (capability probes plus public MLX fallback),
   not by chip-name or OS-name gates.
2. Custom Metal kernels are boosters, admitted per worker by compile plus bounded execution
   probes with expected-value validation. Machines or OS combinations that cannot prove a
   kernel get the equivalent public MLX path for the same request and the same precision.
3. The project operates without a physical device matrix, so it discloses which combinations
   were actually tested and treats community defect reports on untested combinations as
   first-class evidence for fixes and matrix updates.

The previous floor was macOS 26.0. That floor excluded working M-series hardware for no
architectural reason: the Swift menu application compiles with a macOS 14 deployment target
without any availability work, and the probe-plus-fallback architecture already handles GPUs
and operating systems the project has never seen.

## Why macOS 14.0 is the floor

- The bundled MLX stack refuses to build below macOS 14.0
  (`FATAL_ERROR "MLX requires macOS >= 14.0"` in upstream `CMakeLists.txt`). Everything the
  serving core runs on, including the public-MLX fallback paths, inherits that floor.
- The Swift menu application uses no API newer than macOS 14; verified by compiling the
  package with deployment target 14.0.
- Sparkle 2.x supports macOS versions far older than 14, so the update channel does not push
  the floor higher.
- The Rust worker has no explicit deployment-target pin of its own; its floor comes entirely
  from the bundled MLX build.

## Product pin inventory

Any change to the supported macOS minimum must be applied across every surface in this table
in the same change.

| Surface | Pin | Location |
| --- | --- | --- |
| SwiftPM deployment target | `.macOS(.v14)` | `apps/astronomical-menu/Package.swift` |
| Info.plist | `LSMinimumSystemVersion = 14.0` | `scripts/internal/build-macos-app.sh` (written at build time) |
| Release verification bundle | `LSMinimumSystemVersion = 14.0` | `scripts/release/accept-sparkle-update.sh` (written at release time) |
| Sparkle appcast | `sparkle:minimumSystemVersion` | `site/appcast.xml` — regenerated by the release pipeline; never hand-edited. The next Stable cut picks up the 14.0 floor from the release scripts. |
| CI build runner | `macos-26` | `.github/workflows/ci.yml` — build SDK may be newer than the deployment target; kept at 26 because the build machine is macOS 26. |
| Documentation | macOS 14 (Sonoma) and later | `README.md`, `docs/north-star-product-vision.md` |
| Public site | macOS 14 (Sonoma) or later | `site/index.html`, `site/support.html` |

## Tested versus best-effort

| macOS × chip combination | Booster-on (custom kernels) | Booster-off (public MLX fallback) |
| --- | --- | --- |
| Apple Silicon M-series development machine, macOS 26 | tested | exercised by the probe/fallback journey (follow-on issue) |
| Any M-series Mac, macOS 14–25 | best-effort: per-worker probes admit or fall back | best-effort: public MLX path, declared precision preserved |

Unsupported verdicts are proven, never assumed: the probe architecture fail-closes to the
public MLX path when compile, bounded execution, or expected-value validation fails, so
untested combinations degrade to slower serving, not wrong serving.

## Maintenance policy

- Raising or lowering the floor updates this record and every pin above in one change.
- New macOS releases are admitted to the tested row when a release is validated on that OS;
  until then they stay in the best-effort band with probes protecting correctness.
- Community defect reports on untested macOS × chip combinations are accepted, triaged like
  any other defect, and recorded here as tested rows once reproduced or ruled out.
- Chip coverage and OS coverage are always stated separately in public copy; never claim
  "any M-series Mac" while silently blocking on an OS floor, and never claim OS coverage the
  serving stack does not support.
