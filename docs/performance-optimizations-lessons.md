# Performance Optimization Lessons

## First principles

- Rust and C++ are not automatically faster than Python. Python only submits graphs to Apple’s MLX array framework; graph shape and selected Metal kernels dominate.
- Compare the exact model implementation selected by model_type. Qwen3.5-MoE uses qwen3_5_moe, not the similar qwen3_next model.
- Match Machine Learning framework for Apple silicon (MLX) version, model files, prompt, tokenizer, sampling, prefill_chunk_tokens, cache state, and build profile before comparing.
- Measure long-context parity after the runtime chat template is rendered, and pass the same thinking-mode setting to both the prompt renderer and output parser; counting only source text or disabling thinking in metadata produces unlike workloads.
- Source-matched sanitize behavior is part of model arithmetic. Stock MLX-LM 0.31.3 double-shifts already-converted Qwen3.5 and Qwen3.6 normalization weights when MTP tensors are present, corrupting target-only output; apply the checkpoint producer's sanitize correction while keeping MTP construction disabled.
- Use release builds for performance. Debug builds remain useful for correctness only.
- In one-token-ahead decoding, inject budget-control tokens before the model forward and discard any successor predicted from the replaced token. Multi-token prediction may reach the reasoning allowance exactly but must not cross it; resume prediction only after the complete transition is committed to decoder state.
- Compiling only elementwise composites (Swish-gated linear unit, attention gate, sparse/shared expert combination) does not make multi-token prediction faster. Machine Learning framework for Apple silicon (MLX) `compile` must own the whole decode or verify forward: trace once, thread key/value and gated-delta state as explicit compile inputs and outputs, and replay. A growing cache object cannot sit inside the compiled region. Without that, every step rebuilds the full mixture-of-experts tape on the host; multi-token prediction then pays that rebuild for the proposal and again for the two-to-four-row verify, so it loses to one-token decode even at high draft acceptance.
- Wrapping the existing Rust layer loop in `mx.compile` does not create that whole-forward tape. Host integer reads and growing cache objects retrace every step, so the wrap stays a compiled shell around the same launches.
- For a two-row Multi-Token Prediction (MTP) verify window against a long cached prefix, native MLX causal Scaled Dot-Product Attention (SDPA) preserves highest-logit identity with sequential per-row SDPA. The native call still selects the tiled kernel for query length two; sequential one-query vector SDPA remains the faster verify path.
- Do not sort Mixture-of-Experts (MoE) assignments on a two-row verify window. Sixteen assignments sit below the ordinary sort threshold, and forcing a sort changes gathered quantized accumulation enough to flip highest-logit tokens.
- Dense Multi-Token Prediction (MTP) verify rereads the same projections as one decode, so depth-one speculation can outrun target-only decode. MoE verify still routes different experts, so the same depth does not transfer from a dense 27B artifact to a 35B A3B artifact.
- An autoregressive MTP proposal leaves predictor state containing the current target token and every proposed draft except the final draft. Preserve that evaluated state when verification accepts its complete frontier; restore the pre-proposal checkpoint only for partial rejection, and replay only the accepted suffix absent from proposal state. Rebuilding the complete accepted history repeats evaluated head forwards without changing predictor state.

## Mixture-of-experts routing

- Unsorted expert assignments cause scattered expert-weight reads during gathered quantized matrix multiplication.
- For at least 64 assignments, flatten assignments, sort by expert, gather token rows in that order, and pass sorted_indices=true to every routed expert projection.
- Reuse one sort for fused gate/up and down projections. Unfused paths reuse it for gate, up, and down.
- When affine gate and up expert projections share quantization metadata, concatenate their output rows at model load. One gathered quantized matrix multiplication can produce both halves; split once before the Swish-gated linear unit. This removes one graphics-processor launch per sparse layer and remains bit-identical because affine rows are packed independently.
- Bound gate-and-up fusion materialization to one layer at a time, then synchronize and clear reclaimable allocator memory before fusing the next layer. Retaining every original and fused buffer until the end creates a model-scale transient.
- Detach selected lazy expert tensors from their SafeTensors result maps before sequential gate-and-up fusion. Each result-map entry owns its source array, so keeping the maps alive prevents evaluated gate-and-up sources from retiring after the fused layer materializes; allocator cleanup cannot reclaim a buffer that the map still owns.
- Do not retain a shared-expert fusion solely because an isolated projection benchmark removes launches. Repeating a one-row output gate and retaining another complete projection can improve that microbenchmark while failing to improve representative resident REST generation. Require an end-to-end gain before accepting the extra persistent payload and ownership path.
- Compute the inverse sort once, then use a Metal kernel to apply router scores directly to sorted outputs. Restoring [batch, tokens, top-k, hidden] first creates an expensive transient tensor.
- Keep small decode batches unsorted; sorting eight assignments costs more than it saves.
- Native BF16 paged experts should retain their one-weight source layout through bounded reads, page retention, and GPU selection. Converting them to affine parameters or copying selected weights to the host defeats paging and changes precision.
- Do not implement selected native BF16 experts as take_axis(weights, assignment_indices) followed by batched matrix multiplication. That materializes one complete expert matrix per token assignment; a moderate prompt can request a tens-of-gigabytes temporary Metal buffer. Use MLX gather_mm, which reads selected matrix batches inside the multiplication kernel without expanding weights.
- Retain the sorted-expert weighted-sum Metal kernel with the loaded model. Recreating its owner for every layer repeats avoidable graph-configuration work even when the system pipeline cache is warm.
- When production admits only router-requested one-expert pages, size the non-evictable request reserve from the largest model-derived top-K routed page. Multi-token prompt processing may request more unique experts, but that larger selection is temporary or evictable and must pass the per-forward live budget rather than inflate every request's initial reserve.
- Evaluate the compact route bitmap before changing retention, then sample live memory and reserve exact missing expert payload plus one future routed-page reserve. Assignment count is only a fail-closed pre-analysis bound; using it after deduplication evicts warm pages for repeated routes.
- Defer router materialization only for one-token decode, where a small hot route usually hits. Multi-token prefill can select nearly every expert in every layer; executing it with holey page tables corrupts downstream routing evidence and turns exact loading into repeated whole-forward replay. Resolve each layer's compact route bitmap, load its exact missing pages, then execute that layer once.
- Optimize expert-cache topology, not only retained byte count. Spreading a near-model-sized budget across almost-complete layers preserves most bytes but still forces a router wait and repair load at every layer. When a dense prefill route leaves no more unselected experts than it selected and the complete layer fits beside existing complete layers, finish that layer. Preserve complete layers and use the remaining bytes as a streaming pool for incomplete layers; explicit memory pressure may demote one whole layer at a time.
- Complete resident and Rust-streamed layers should use one ordinary expert-axis tensor per parameter with Machine Learning framework for Apple silicon (MLX) `gather_qmm` / `gather_mm`. Do not restore custom page tables for streamed layers without representative proof.
- Compare packed affine `gather_qmm` against `dequantize` plus `gather_mm` with a bounded floating-point tolerance, not bit identity. The packed and dense kernels accumulate in different orders even when they consume the same dequantized weights.
- Use `gather_qqmm` only when the model's execution contract already supplies quantized input activations. Astronomical's gathered expert paths retain floating-point activations and quantize only stored weights; Laguna's compressed input-activation declarations are validated artifact metadata, not an active quantized-input execution path. Quantizing activations solely to select this operation would add work and change model precision.
- `PagedBufferSlot::view` must mark leaves `Status::available` before they enter ordinary MLX graphs. The constructor `array(shape, dtype, nullptr, {})` leaves `status=unscheduled` with a null primitive. Page-table execution only borrows graphics-processor addresses, so it tolerates that state; contiguous `gather_qmm` / `gather_mm` evaluates the leaves and fails with "array without a primitive" unless status is corrected at view construction.
- **Retired page-store lesson:** the custom C++ paged-buffer expert store was numerically correct but created severe end-to-end memory and scheduling overhead for whole-layer prefill. On the same Fable 4,096-token, two-by-2,048-token journey under a 39 GB ceiling, the C++ path left the first chunk running for roughly 80 seconds near 36 GB active memory, while restored Rust bounded SafeTensors streaming completed the request in 8.933 seconds near 3.5 GB active memory with zero logit delta in the paired parity contract. Prefer the simplest ordinary Machine Learning framework for Apple silicon array graph that satisfies ownership and precision; native language placement, reusable slots, and fewer host allocations do not establish performance.
- For multi-token mixture-of-experts prefill, let Rust build one exact complete-layer bounded SafeTensors page, execute ordinary `gather_qmm` or `gather_mm`, and release the operation-local owner naturally. For one-token decode, build only the deduplicated top-K route. Avoid custom page tables, indirect graphics-processor addresses, immutable native snapshots, and retirement protocols unless a representative end-to-end gate proves they outperform ordinary arrays.
- Trace the complete input/output ownership path before adding a host-buffer zero-copy API. MLX SafeTensors loading allocates the final shared Metal buffer before invoking the reader, so Astronomical's positional reader writes file bytes directly into graphics-processor-addressable MLX storage; there is no intermediate expert payload buffer or later host-to-MLX copy to remove.
- A custom MLX C reader bypasses the path reader's internal large-read partitioning. Partition only contiguous source intervals larger than 32 mebibytes, cap each interval by available processor parallelism and four workers, and retain one positional read for smaller routed pages; this restores positional-read concurrency without fragmenting latency-sensitive reads.
- A mandatory multi-token mixture-of-experts read may transfer its already-loaded complete layer into stable retained ownership when the composed budget targets that layer. Materialize once, commit atomically, and reuse it across later chunks; do not reread storage solely to populate retention.
- Partial retained pages remain valuable when execution partitions assignment positions between retained and missing pages, runs each assignment once, adds their sparse outputs, then combines the shared expert once. Score-masking both complete top-K sets doubles gathered matrix work; falling back to one complete temporary page discards most retention value.
- Cached-plus-streamed remap must use assignment positions in `selected_indices`, not unique expert-id ranks. Unique ranks do not cover the assignment count and abort the compact `take_axis` remap.
- Do not grow a packed expert page with `concatenate_axis`. MLX arrays are immutable, so concat copies the whole retained tensor. Stream only the missing experts as a second page, or replace the page; do not append.
- Prefill cannot use the one-token cached-plus-streamed layout. Hidden states stay `[batch, tokens, hidden]` while cached-plus-streamed sides are compact one-dimensional assignment lists. A multi-token miss must not call decode cached-plus-streamed.
- Replacing the packed page on every prefill chunk discards previously cached experts. Smaller SSD chunks then reread more unique sets. On the oQ8e long-conversation journey, 512-token SSD chunks measured 64 prefill tokens/second and 79 GB of decode source reads versus 125 prefill tokens/second and 21 GB of decode source reads at 2048-token chunks.
- Prefill cached-plus-streamed that keeps the first packed page and streams only misses preserves retained expert payload (29.573 GB / 8848 groups on oQ8e) and can run a later chunk at ~1400 interval tokens/second. It does not by itself reach ~300 official prefill tokens/second: misses that are not stored still cost ~10 s of positional reads on the next chunk, and the same journey measured 98 official prefill tokens/second and 43 GB of decode source reads. Compact assignment rows must `scatter_add` onto tokens; `put_along_axis` would drop a second expert on the same token. Production prefill must not use that two-gather path: graph construction for 40 mixed layers measured ~70s. Prefill misses replace the packed unique-expert page and run one `gather_qmm`. Decode may insert missing rows into unprotected slots; if they will not fit, replace the page.
- Generation preparation and finalization should reconcile accounting, not scan storage. Release temporary request pressure, preserve fitting complete and partial pages, and let the first mandatory decode route populate only an empty layer. An explicit idle user ceiling increase is different: it may atomically scan and promote the complete expert owner before acknowledging the change.
- Keep a stable complete-layer foundation and an elastic routed-page overlay. Under pressure, evict low-coverage routed pages before complete layers; an existing partial page remains useful because cached-plus-streamed execution streams only exact route misses.
- Do not coalesce an adaptive terminal remainder into an oversized candidate. The resulting partial forward cannot become candidate evidence and can enlarge generation-start work; continue with admissible full-capacity candidates until only a remainder below the smallest candidate remains.
- Paged prefill is different: each forward streams every unseated complete MoE layer. On the oQ6e 20 GB long-conversation journey, 4,401 tokens at 2,048-token chunks became 2,048 + 2,048 + 305, and the 305-token tail paid a full leftover-layer sweep (~0.59 s). Fold a trailing stub smaller than one configured chunk into the current paged forward. Resident remainders stay exact. Capacity recovery still halves if the folded forward cannot fit.
- Do not infer first-decode latency from the first generated-token progress event: hidden reasoning, output parsing, and one-token-ahead execution can make that timestamp represent a later boundary. Time the first model forward through token synchronization inside the engine, emit it once, and subtract it from the supervisor's preparation-to-decode wall clock so preparation and first decode remain independently attributable.
- In an August 2026 Romeo-and-Juliet 26 GB acceptance run, an append-only request reused 11,520 cached tokens, prepared generation in 52 ms with zero preparation source reads, completed its first decode forward in 230 ms, and finished with 6 complete plus 34 partial layers using 3.375 GB of retained expert payload. The request measured 1,202.85 prefill tokens/second, 18.12 generation tokens/second, 99.797 GB of logical expert source reads, and a 25.586 GB request peak. Keep these independently attributed values in the regression journey so topology improvements cannot hide storage-read, first-decode, or peak-memory regressions.
- Streaming grain for multi-token mixture-of-experts prefill is the complete sparse layer, not routed expert groups. Build one operation-local complete-layer page in Rust; use temporary routed top-K pages only for one-token decode.
- Do not use cyclic whole-layer least-recently-used as the primary residency policy. Decoder layers are visited in fixed order, so a cache smaller than the layer count can thrash every visit. Prefer a deterministic complete-layer set packed into budget `P` plus one complete-layer streaming slot `S`.
- One owner must compose MLX RAM as `retained_expert_budget_bytes = mlx_active_memory_ceiling_bytes - model_core_payload_bytes - context_window_reserve_bytes - activation_headroom_bytes - expert_stream_slot_bytes`. Bootstrap context reserve at 1 GB SI. Subtract separately charged transient evidence before learning persistent context, and reserve a complete layer for multi-token prefill but only the model-derived routed page for one-token decode.
- Prefill may stream every expert of a decoder index, but it must seat that complete page only when the phase plan named the layer `PromoteCompleteOnMandatoryRead`. Leftover-RAM adopt during the first 2,048-token chunk can pin 25 complete oQ6e layers (~16.4 GB) because admission also installs a 17.5 GB request-pressure cap that ignores activation headroom and the stream slot. The next complete-layer read then misses the 20 GB ceiling, recovery refuses the same chunk, and the sizer halves to one-token forwards. Operation-local complete-layer streams after the planned set keep the large chunk alive.
- A seated complete expert page remaps every route on-device, so a cache hit must not copy router indices to the host. Prefill miss still copies then streams the complete page: merging attention, the SSD read, and MoE into one eval raised the second-chunk peak and halved a 1,792-token chunk. Adopt the lazy streamed page and let the layer-interval eval materialize it; a separate weight eval before adopt double-synced every seated layer on the first chunk. Intermediate persistent-cache chunks should skip the vocabulary head; checkpoints store decoder state, and `lm_head` is only required when sampling. Clamp cache-enabled prefill to one durable boundary only when the configured chunk would cross more than one; a 3,840-token cache block otherwise splits 2,048-token SSD streams into 1,792 plus a 561-token stub that rereads every uncached complete layer.
- A forward-admission reserve is effective only when retained ownership consumes it. Constrain mandatory-read promotion to the exact strict-ceiling capacity left after persistent growth, one phase-correct expert page, and expected transient work; a no-op handoff lets retained layers invalidate an otherwise correct admission proof.
- Post-forward peak memory includes expert pages promoted during that forward. Subtract newly retained expert payload before teaching the context-and-activation budget, or the next plan reserves those experts twice and discards the topology it just created.
- Prefill leftover-budget refresh must not evict complete layers this request already seated. Learned context reserve can shrink the leftover number after chunk one; applying that smaller number as the cache ceiling throws away a paid page and later chunks stream it again. Floor the Prefill cache ceiling at current complete-layer payload. Real capacity failure still shrinks through the request contract. Unseated leftover layers still stream every chunk: zero leftover reread requires those pages to fit, not a tighter leftover plan.
- Keep the geometry-derived cold prefill activation floor after cheaper observations. Letting one smaller chunk lower that floor can expand complete-layer retention before a later larger chunk and reproduce the near-ceiling scheduling cliff.
- Keep every cross-component fit, reclamation, demotion, retry, residency, and live-ceiling decision behind that memory owner. Paging, caches, and model execution should report exact requirements and enact typed plans; letting each mechanism recombine the same ceiling and reserves creates conflicting retention limits, avoidable eviction, and repeated solid-state-drive reads.
- Derive an adaptive image model's minimum MLX ceiling from its smallest safe streamed geometry, not the residency selected under the current ceiling. Take the maximum of streamed text, fixed transformer execution with no retained blocks, complete variational autoencoder decoding with workspace and RGB output, and RGB plus PNG plus base64 encoding overlap; otherwise a high initial ceiling retains extra blocks and falsely prevents a safe later reduction.
- Distinguish predicted forward peak from recovery policy in expert-demotion decisions. A second copy of the learned transient high-water window is not simultaneous expected usage. Log stable, peak, and recovery projections separately and identify a recovery-only trigger before demoting a complete resident model; otherwise conservative retry headroom can force solid-state-drive streaming even when the measured forward peak fits the approved transient ceiling.
- A no-op attribution recorder does not make its arguments free. Guard diagnostic manifest construction, graphics-processor route readback, source-interval traversal, clocks, and allocation behind the enabled boundary so disabled serving does not compute evidence that will be discarded.
- Optional request-steering files belong behind the runtime gate, an asynchronous bounded read, and the same start/end attribution used by the rest of the serving path. Synchronous or unbounded reads before queue admission turn a small experiment into hidden request latency and memory growth even when model execution is unchanged. Attribution clock or writer failures must remain best-effort on this boundary so optional diagnostics cannot suppress valid steering input or otherwise alter inference behavior.
- `async_eval` is not a retirement or validation barrier. A true downstream `eval` root, or exact-stream `synchronize` only when no retained root exists, is the safe host completion API for expert-page correctness.
- MLX 0.32.1 `Event::set_error(Error&)` retains only a pointer to the supplied error. An external asynchronous producer must publish the error before host-signalling a failed shared event, queue ordering through `Event::wait(stream)`, and retain the error until MLX's command-completion handler copies it. Immediately committing that wait with a completion-owned lifetime preserves device ordering without adding a successful-path host synchronization or depending on the thread that releases the caller's handle.
- Presence must be checked inside paged gather kernels. Page-table addresses alone do not prove residency; missing pages must not dereference weight pointers.
- Validate this with a controlled local mutation. Disabling only sorting reduced measured prefill from about 979 to 444 tokens per second.

## Custom recurrent Metal kernel

- MLX custom Metal template arguments are declared inside the generated kernel function and are unavailable to global header declarations. Parameterize header helper templates explicitly with quantization bits and group geometry, then derive template-dependent constants inside the kernel body; otherwise first-use pipeline compilation fails even though graph construction succeeds.
- A token-by-token recurrent loop built from generic MLX operations creates excessive graph nodes and kernel launches.
- Fuse the complete gated-delta sequence recurrence into one Metal kernel while keeping recurrent state in 32-bit floating point.
- Construct and retain the kernel object once with the loaded model. Never recreate it per layer, chunk, or token.
- Match upstream grid, threadgroup, pointer arithmetic, data types, state layout, and grouped-head mapping exactly.
- Keep an operation-based implementation as a numerical reference test, not as the production path.

## Runtime T versus template constants

- T is the current sequence token count.
- Pass T as a zero-dimensional MLX integer array at runtime.
- Do not make T a Metal template argument. That compiles a separate kernel variant for every chunk length, including the final partial chunk.
- Template only stable specialization values: input type, state type, head counts, and head dimensions.
- A runtime scalar preserves one compiled kernel across configured prefill chunks, partial chunks, and one-token decode.

## Metal compilation and dispatch

- Ahead-of-time and just-in-time Metal builds can contain different kernel families; this is not merely a startup-versus-binary-size choice.
- The prior ahead-of-time build targeted macOS 14. MLX therefore defined MLX_METAL_NO_NAX and excluded its Metal 4 matrix kernels.
- MLX source uses nax as an internal label for those Metal 4 kernels.
- Enabling just-in-time Metal compilation lets MLX inspect the operating system and Apple graphics-processor generation, then select the fast kernels or a compatible fallback.
- Read CMake branches and preprocessor definitions. A build flag can silently change runtime dispatch while preserving correct output.
- Identical Float32 power graphs can round differently under a generic precompiled Metal library and hardware-selected just-in-time Metal kernels. Generate exact numerical acceptance values with the production Metal path, and verify graph parity separately instead of importing Python-wheel values into a just-in-time runtime.
- Ahead-of-time kernel lookup can hide an invalid just-in-time template declaration because the precompiled path selects only by kernel name. Pass specialization arguments only to the templates that declare them, and prove both fast and slow quantized matrix-vector geometries through the production just-in-time path.
- First-use compilation can make a correct fast path appear slow. MLX stores compiled Metal pipelines in the system cache and reuses them across processes and reboots.
- After a process restart, the first fully resident Laguna-XS-2.1-oQ8e prefill can still read tens of gigabytes from solid-state storage while status reports complete expert residency. One 23,864-token first request measured 271.7 prompt tokens per second with 24.53 GB of process disk reads; the next warm unique 23,863-token miss on the same loaded worker measured 1,396.9 prompt tokens per second and stayed at 39 of 39 resident layers. Compare a later warm unique miss before concluding the kernels regressed.
- A fully resident 35.52 GB Laguna-XS-2.1-oQ8e prefill that evaluated all 40 decoder layers as one Machine Learning framework for Apple silicon tape spent 109.2 seconds and read 44.00 GB from disk, with the second 2,048-token chunk alone taking 88.9 seconds. Intermediate `mlx_async_eval` after each decoder layer retires that layer's command buffer before the next layer is encoded. Do not keep one whole-model prefill tape against a 40.00 GB ceiling.
- That one-tape disaster is ceiling pressure, not a universal rule. OMLX/mlx-vlm prefills Qwen3.5 MoE with one `language_model(...)` tape and one `mx.eval` of cache state per 2,048-token chunk. On fully resident Ornith-1.5-35B-A3B-oQ6e-mtp (~30.17 GB on disk, 38 GB ceiling), that path measured 11,106 prompt tokens in 6.55 seconds (~1,671 tok/s). Astronomical's default `prefill_graph_submission_layer_interval=1` on the same model measured 185 tok/s for 7,000 tokens; later 2,048-token chunks were only 410 to 680 tok/s. Chunk size matches OMLX. The gap is about 40 host graph traversals per chunk versus one eval.
- `mlx_async_eval` host overhead is proportional to the number of lazy graph nodes that must be traversed, not just the number of calls. On a 39-layer Laguna-XS-2.1-oQ8e mixture-of-experts model, interval 1 (submit after every layer) costs approximately 21 milliseconds per call for a total of 4.1 seconds across 195 calls over five chunks. Interval 5 (submit after every fifth layer) reduces the call count to 35 but each call traverses five layers worth of lazy graph, costing approximately 105 milliseconds per call for a similar total of 3.7 seconds. The total host traversal cost is essentially fixed by the total number of graph nodes in the chunk regardless of how many submit boundaries divide them. For a dense model like Ornith-Qwen-1.0-35B where each layer has fewer graph nodes, per-call overhead drops to approximately 2.5 milliseconds because there are fewer Machine Learning framework for Apple silicon primitives per layer to traverse.
- Resident prefill uses `prefill_graph_submission_layer_interval` (default 0: one lazy tape, matching OMLX/mlx-vlm). SSD-paged prefill uses `experimental_ssd_paging_prefill_graph_submission_layer_interval`. One-token resident generation stays at interval 0. The two prefill intervals are independent; changing one cannot alter the other mode.
- Kernel name, source, template values, compile options, and target architecture affect cache identity.
- Report cold and warm kernel-cache results separately.
- Put prompt-only custom matrix kernels behind the token-count check first. Decode visits the wrapper in every layer for every token; environment, capability, and module inspection before the shape rejection can erase decode gains.
- For long affine-quantized prompt matrices, compare a model-shaped Metal 4 tile with the stock quantized matrix multiplication. Keep one-token decode on its measured matrix-vector or gathered path; a prompt tile is not automatically a decode kernel.
- A synchronous `mlx_eval` call includes serial dependency traversal, graphics-processor command encoding, first-use Metal library and pipeline compilation, and the final completion wait. Do not label its complete duration as graphics-processor synchronization or infer the active resource from wall time alone.
- `mlx_async_eval` finalizes and commits the current graphics-processor command buffer. Submitting each completed decoder layer during multi-token prefill gives macOS scheduling boundaries without splitting optimized matrix kernels. Keep the layer interval configurable; zero remains useful only for controlled comparison.
- Do not apply an attention-dispatch workaround designed for Apple graphics processors without Metal 4 matrix hardware to newer hardware without measuring the model's exact head geometry. MLX routes unsupported fused-attention widths through stock matrix kernels that can outperform query tiling substantially on newer Apple graphics processors.
- Treat fused-attention head dimensions as model-driven dependency requirements. A synthetic configuration-parser case does not justify a runtime benchmark or specialized acceptance lane; add that coverage when an executable installed model reaches the geometry, then verify dispatch, peak allocation, and end-to-end latency together.
- Shapeless `mlx_compile` avoids shape-specific graph retracing, but its first evaluated compiled primitive still builds a Metal source library and compute pipeline. The first request can therefore saturate one host core even when later identical requests spend nearly all host time asleep while the graphics processor runs.
- MLX protects its per-device library and kernel maps with exclusive locks and encodes one evaluation tape serially. A Rayon loop around one MLX stream cannot parallelize that first-use work; split asynchronous evaluation submission from explicit stream synchronization before deciding whether host parallelism is useful.
- `mlx_async_eval` can traverse the lazy graph, compile Metal libraries and pipelines, resolve dependencies, and wait on internal Metal events before returning. An explicit stream synchronization measures only the remaining graphics-processor completion time.
- Correlate process samples with model-loading and generation timestamps. Bounded model-loading read workers can raise process central-processing-unit use before prompt processing starts, so a whole-request sample cannot attribute that work to prefill.
- For 256-wide attention heads on Metal 4 matrix hardware, split each head across two single-instruction multiple-data groups and use block matrix operations.
- Maintain online-softmax state per block instead of materializing the quadratic attention-score tensor.
- Gate specialized attention by hardware, data type, mask, and measured shape. Retain the unfused graph for unsupported shapes.
- Before adding a custom decode split, inspect Machine Learning framework for Apple silicon (MLX) fused scaled dot-product attention (SDPA): for one to eight query tokens and sufficiently long grouped-query key/value state, it already selects a two-pass partitioned Metal kernel. Measure the active dispatch before duplicating it with a paged-attention layer.
- Preserve MLX automatic key/value partitioning for long grouped-query decode. A one-partition control removes useful graphics-processor parallelism, so a custom paged-attention layer must prove an additional end-to-end benefit rather than replicate MLX splitting.
- MLX v0.32.1 rounds the MLX_SDPA_BLOCKS environment variable override up to a multiple of 32 (MLX pull request 3875). Before that fix, non-multiple-of-32 values silently corrupted decode attention output because the two-pass vector SDPA reduction loops divide by BN = 32 and silently dropped tail partials. All built-in block choices (32 through 1024) are already multiples of 32, so the override is the only way to reach the broken path. The rounding makes the SDPA block-count override safe to use as a decode attention tuning lever without manual alignment validation.
- MLX v0.32.1 validates the threadgroup size for the single-pass sdpa_vector dispatch (MLX pull request 4018). Before that fix, a register-limited pipeline that exceeded maxTotalThreadsPerThreadgroup would silently return all zeros because the Metal driver dropped the dispatch without error. Current supported models do not hit this limit, but the validation ensures that a future large-head-dimension model will fail loudly rather than silently corrupt decode output.
- Keep a full rotating key/value cache in physical ring order during one-token decode. Unmasked attention is invariant when keys and their matching values share the same permutation, so rebuilding chronological order adds slice and concatenation work without changing output. Reconstruct chronological order only for multi-token causal attention, where key position controls visibility.
- Quantized matrix multiplication split-K dispatch can change bfloat16 reduction order when output row count changes. Once row work already exposes enough threadgroups, cap the row-count contribution to split-K selection so equivalent prompt partitions retain one reduction topology and exact recurrent state.

## Compiled graph composites

- Python decorators in the MLX language-model toolkit still change native graph execution. The equivalent C path is an owned mlx_closure passed through mlx_compile.
- Compile only composites isolated by controlled reference mutations. For Qwen3.5-MoE decode, shapeless native-dtype SwiGLU fusion matters; compiling sampling, precise gated normalization, or decay arithmetic did not.
- Retain one shapeless compiled SwiGLU with the model and reuse it across expert layers and prompt or decode shapes.
- Keep mixture-of-experts SwiGLU in the activation dtype. Reserve 32-bit floating-point casts for the gated normalization that requires them; unnecessary precision adds conversion work and can inhibit the intended fused path.
- Router probabilities may remain 32-bit floating point through weighted expert multiplication and accumulation, but cast the reduced output back to the expert activation dtype before adding the residual or shared expert. Architectures that apply router weights to expert inputs must likewise restore the hidden-state dtype before gathered matrix multiplication. Otherwise, one-token routing can silently widen every downstream layer or expert projection and disable Machine Learning framework for Apple silicon low-precision Metal matrix kernels. Assert one dtype contract across sorted reduction, unsorted reduction, empty assignments, and input-weighted routing.
- mlx_closure_new intentionally returns a null-context output placeholder. Accept it only before mlx_compile, then require compilation to populate it before application.
- A Rust callback invoked through C must own every temporary MLX handle, return status codes, and never unwind across the foreign-function boundary.
- Benchmark compiled composites separately for multi-token prefill and one-token decode. Full-attention output gating, gated-delta decay arithmetic, and sparse/shared expert combination can favor prompt processing, while the shapeless precise SwiGLU graph also improves one-token decode.

## Cache types are different

- Do not confuse model state, the MLX allocator cache, and the system Metal pipeline cache.
- Cargo `OUT_DIR` follows package identity, not native binary compatibility. - GitHub pull-request caches are scoped to the pull-request merge ref and cannot seed the default branch. Cancel only superseded pull-request verification; serialize default-branch native publishers without cancellation so a later lightweight merge cannot discard the reusable cache.
- Model state contains full-attention key-value tensors, linear-attention recurrent state, and convolution state. Clearing it changes generation.
- The MLX allocator cache holds reusable memory. Clearing it does not clear model context, but retaining too much can trigger a long-context throughput cliff.
- Treat the macOS GPU wired-memory recommendation as a numeric admission ceiling, not permission to enable MLX per-buffer wired residency. On macOS 26.5.2, allocation-pressure cache reclamation entered MLX residency-set removal and triggered an IOGPU prepare-count-underflow kernel panic. Apple documents that residency-set state is not synchronized between the central processing unit and graphics processor. ## Sampling

- Keep softmax, top-k, top-p, temperature scaling, and categorical sampling on the graphics processor.
- MLX v0.32.1 uses inverse cumulative distribution function sampling for one distribution with a nonempty sample shape, reducing memory from the category-count times sample-count product to their sum. Fixed keys remain deterministic but intentionally produce a different identically distributed sequence than the older Gumbel-max algorithm; use statistical contracts for cross-version acceptance.
- Compiled sampling closures require MLX v0.32.1 or later. Its random-state sentinel resolves the calling thread's local state, preventing compilation on one thread from freezing that thread's state when another thread invokes the closure.
- For descending top-p probabilities, use an exclusive cumulative sum. Keep the candidate that crosses the threshold.
- Test top-p independently with a dominant token and a threshold-crossing token before testing a full model.
- Prove structured tool generation with the model family's documented sampling policy. Highest-logit decoding can loop over narrated intent and waste the output budget even when the prompt template and parser are correct.
- Multi-token prediction (MTP) verification is not automatically a throughput win. Warm both paths, bracket MTP with leading and trailing target-only controls, compare against the faster control, preserve target output as the source of truth, and retain production MTP only when it improves end-to-end request latency.
- Draft-assisted sparse prefill pays draft scoring before target savings. A short prompt can regress even when selected target work is smaller; prove the threshold bypass separately from long-context end-to-end benefit and keep the feature bypassed below the configured minimum.
- Draft sparse-prefill lookahead must see the complete prompt. Smooth every layer and head attention map before taking their maximum because smoothing after the maximum changes token ranking. When the target reserves the final prompt token for generation startup, include that token in draft scoring but exclude its score from sparse target selection to avoid duplicate target work.
- MLX native rotary positional embedding accepts one dynamic offset per batch row, not one offset per token. To preserve arbitrary sparse prompt positions without custom trigonometry, transpose one text sequence so selected tokens become one-token batch rows, apply dynamic native rotary positional embedding with the selected position vector, then transpose back before attention. This retains one sparse target forward, native low-precision Metal arithmetic, and compact key/value state.
- Keep draft importance pooling, chunk averaging, top-chunk partitioning, and selected-position expansion as lazy MLX arrays. MLX argpartition, argsort, take, reshape, and broadcast arithmetic can select sparse prompt chunks on the graphics processor; copy only the bounded final selected-position vector to request orchestration. Copying every importance score to Rust and sorting there adds a synchronization boundary and scales host work with prompt length.
- Keep the complete prompt token-index tensor on the MLX device after sparse selection. Use the MLX C API take_axis gather with each selected position tensor, then pass the gathered token indices directly into the embedding lookup; rebuilding selected token IDs in Rust and uploading them per chunk adds avoidable host work and graph boundaries.
- Full-attention state can own a capacity-rounded MLX slab larger than its active token offset. Slice the active sequence range on the graphics processor before solid-state-drive serialization; persisting unused capacity writes avoidable bytes and makes restoration infer the wrong logical state length.
- For a model with tied input and output embeddings, retain one reference to the input embedding arrays for output projection. Do not require or materialize a duplicate language-model head payload.
- A depth-one MTP path only becomes faster when the target model verifies a two-token window, accepts the matching draft prefix, and emits the accepted draft without another target forward. Merely drafting one token and comparing it against the next ordinary target step adds work without acceleration.
- Admit MTP before its draft mutates request state, charging the exact rounded physical growth of its independent key/value slab together with target verification growth. If optional speculative growth cannot fit, disable MTP for that request and attempt ordinary target decoding instead of rejecting work that may still fit. Do not add a fixed MTP reserve: exact model-derived growth preserves aggressive memory use without hiding an allocation from the adaptive guard.
- Project predictor history updates in their real forward boundaries. Combining two sequential one-token updates into one two-token estimate can undercount slab growth when the first update fills the current capacity and the second allocates a complete growth step.
- Keep the MTP history entry created from the confirmed current token when its draft is rejected. Only the draft is unconfirmed; rolling back the predictor entry discards committed history and misaligns later proposals.
- Do not append another predictor-history row after accepting a depth-one draft when the proposal forward already committed the current predictor input. The deferred bonus proposal advances the next predictor position; an extra accepted-draft prefill advances predictor state faster than target state and adds avoidable head work.
- Prove MTP with representative output lengths. A short all-accepted sample can hide later rejection-state defects, two-token target-forward numerical drift, and acceptance rates too low to repay proposal and verification work.
- Use approximately 1,000 input tokens and 1,000 generated tokens for model-generation throughput claims. Shorter probes may diagnose mechanics but are not performance evidence.

Mathematically equivalent two-token verification can use different multi-token kernels and accumulate a different decoder state from repeated one-token decode, so require complete target-verifier outcomes and no operational fallback rather than universal byte-identical output.

Quantized matrix multiplication, expert-page geometry, and multi-token recurrent execution can select different arithmetic even when every draft is target-verified. Sequential accepted-state reconstruction preserves parity but removes the speculative speed benefit; preserving both requires an exact multi-row kernel route rather than queue or cache workarounds.

- Keep raw throughput gates free of performance attribution and adaptive memory-admission sampling. Prove attribution and memory safety separately; clock reads, allocator snapshots, and peak resets can change the result being measured.

## Chunking

- Chunk size is not an independent tuning knob. Re-tune it after changing kernels, routing, or cache layout.
- Before fast expert and Metal kernels, 512-token chunks beat 2,048-token chunks. After both fixes, 2,048 became much faster.
- Larger chunks reduce graph and launch overhead but increase attention work and peak memory.
- Re-test power-of-two chunk boundaries after graph or kernel changes. Quantized matrix-multiplication dispatch can make 8,192 tokens materially faster than nearby non-power-of-two sizes; do not infer intermediate-size performance by interpolation.
- Treat any large fixed chunk as a benchmark-only upper bound until it passes the same output and memory acceptance. Deterministic fixed sizing uses the configured chunk directly; proven memory capacity can halve the attempted size after a pressure event.
- Persistent prompt-cache block size must not cap model-forward size. Capture exact intermediate convolution and recurrent state during one large forward and persist fixed-size blocks in prompt order. Include reclamation and topology-transition cost.
- Keeping extra complete layers during prefill only helps when they fit the leftover expert budget. At half on-disk model size, one extra complete layer cut append reread by about two gigabytes and left suffix prefill essentially unchanged; the remaining streamed tail still reread every chunk. Zero reread requires the tail to fit, not only a commit-after-read.
- A larger paged `fixed_ssd_streaming_prompt_processing_chunk_size_tokens` does not execute while publication still clamps each forward to the next durable block. On a hybrid-resident cached Romeo and Juliet suffix, an 8,192-token paged chunk still ran as two ~3,840-token forwards and reread the same streamed complete-layer payload. Raising the cache block to 8,192 to match that chunk restored a shorter prefix and made first output slower. Do not ship an automatic paged-chunk default until executed chunk size actually grows.
- Before prompt-cache restore, charge restore overlap and prefill activation against the seated expert owner. A resident model that fits a short first request can still kill a longer cached append if restore runs on top of every expert. Demote or reclaim first.
- Complete-residency activation headroom for prefill is three complete layers or the observed transient high-water, not one tenth of the whole expert payload and not a single layer. One layer let a 38.6 GB oQ8e model seat all 41 layers under a 40 GB ceiling; a 10k-token cold prefill then stalled at 45–90 tokens/second and missed a 115-second bound because later chunks peaked at 40.08 GB. Three layers is the measured first-chunk overshoot on that near-disk shape. The matching journey then completed a cached oQ8e append at 1,428 tokens/second. Decode may still use one layer once a decode high-water exists.
- Context-window reserve must grow with unmeasured prompt tokens. A 1 GB bootstrap or a smaller measured bucket cannot authorize packing every leftover byte into complete layers; a later cached suffix then has no room for key/value growth and either stalls the GPU or rejects the request. Project the unmeasured token delta from decoder-state bytes per token.
- Retired: walking one complete expert set across suffix chunks, and prefetch of unevaluated MLX handles. Those did not overlap real SSD reads and treated a decoder index as the cache unit. Prefill and decode now retain individual routed experts. A later token that needs a new expert streams that expert and evicts the least-used expert under the byte ceiling.
- Treat an active-memory ceiling rejection as a request failure, not a worker death.
- Prove chunk sizing through the production configuration path as well as fixed-size tests.
- A fixed start-distance filter plus smallest-first exploration did not stabilize adaptive chunk selection in production. Do not use an arbitrary positional window as a substitute for a validated cost model or a controlled same-condition experiment.
- Retire online chunk exploration when persisted learning and positional comparability do not improve end-to-end prompt latency over a chosen deterministic fixed size. Model-forward measurements alone cannot justify spending user latency on exploration.
- Keep the final partial chunk on the same runtime-T kernel path.
- Measure peak physical footprint together with throughput; a faster chunk is invalid if it makes the laptop unsafe.

## Profiling

- Label every throughput value by its timing boundary. Cumulative request prompt rate includes orchestration and waiting, while per-chunk model-forward rate covers model-forward time only; presenting both as unlabeled tokens per second makes valid measurements look contradictory.
- Separate central-processing-unit graph construction from graphics-processing-unit evaluation.
- Rust graph construction was already fast. Synchronizing each layer showed that excess time was inside Metal evaluation.
- Per-layer synchronization changes scheduling. Use it only to locate a subsystem, then remove it before final measurement.
- A long Machine Learning framework for Apple silicon synchronization wait identifies a host blocking boundary, not a slow graphics-processor kernel. Use Xcode Metal profiling at that boundary before changing model code.
- A long-lived attribution writer must compare the open file identity with the configured path before each report. If log rotation removes or replaces the path, reopen it so profiling continues without restarting inference.
- Start steady-state generation timing after the first output token. A cumulative clock that includes prompt processing creates artificial acceleration as more output tokens amortize prefill.
- The first layer pass mixes page faults, kernel compilation, and execution. Repeat with warm weights and pipelines before judging steady state.
- Mutate one reference behavior at a time. This identified expert sorting and Metal dispatch without guessing.
- Use 1,024 input tokens and 1,024 output tokens for representative generation measurements. Keep shorter probes only as development diagnostics.
- Do not compare two request modes as throughput evidence when their observed expert-memory modes differ. Record the attribution, then repeat with matching residency and paging state before drawing a performance conclusion.

## C++ and Rust build boundary

- A Rust toolchain change invalidates compiled artifacts and compiler-cache entries by design. Measure commit-verification steady state only after that compulsory cold rebuild, and keep the cold path bounded rather than weakening cache correctness.
- Benchmark compiler caches separately on Rust artifacts and the complete native C++ graph. Zero-copy restoration does not guarantee lower wall time when cache-key preprocessing dominates, and a wrapper that performs well for Rust can regress a large MLX C++ rebuild.
- Keep Cargo profiles, features, compiler flags, and target directories stable during Machine Learning framework for Apple silicon (MLX) iteration. Changing them invalidates native CMake paths; zero sccache hits across distinct artifact graphs does not indicate a broken wrapper.
- Cargo does not garbage-collect obsolete hashed build generations. Keep the routine edit loop on one stable graph, but give release and acceptance journeys a unique marker-owned target that is removed on success, failure, or interruption. Preserve reusable compiler output in a separate compiler cache so bounded artifact retention does not require repeated compilation.
- Compiler-cache lifetime counters cannot attribute one verification run. Compare bounded cold and warm commands on the same artifact graph, and use Cargo timing reports for compilation ownership.
- When required Rust boundaries share a profile and Cargo can select them together, compile them in one invocation and execute them in one follow-up invocation. Repeating equivalent Cargo orchestration obscures attribution without increasing coverage.
- Keep compatibility-keyed native products outside Cargo output when they are safe to reuse across builds. Remove obsolete native build trees across current and retired Cargo generations only while holding every affected Cargo profile lock and only after the reusable store is authoritative; otherwise a disposable target merely shifts repeated C++ compilation into every journey.
- A shared cache becomes reusable only after its producer finishes publishing it. Concurrent continuous-integration builds with the same new native-input fingerprint can both restore older fallback state and independently rebuild MLX/MLX-C; coordinate those producers and label timing evidence as primary-hit, fallback-hit, or miss before attributing the delay to Rust compilation.
- Turning a feature-gated CMake target off does not delete an archive produced by an earlier configuration in the same output directory. Remove stale optional archives and test executables explicitly when the feature is disabled so production artifact audits reflect the active graph.
- Native MLX and the final Rust binary must agree on the minimum macOS version.
- Static MLX release objects use Clang availability checks. Link the active Xcode libclang_rt.osx.a runtime, discovered through xcrun, or release linking can fail on ___isPlatformVersionAtLeast.
- Bind only required C functions, but update the allowlist when adopting upstream operations such as argument sorting, floor division, compiled closures, and custom Metal kernels.
- Apply native dependency patches to the pinned source archive during configuration and make Cargo track each patch as a rebuild input.
- MLX C application programming interface (MLX-C) v0.6.0 needs release-specific patches for the Machine Learning framework for Apple silicon (MLX) v0.32.1 Fast Fourier transform and thread-local compile-cache parameter changes. Keep them visible and fail-closed so later upstream interface changes cannot silently alter native behavior.
- MLX Fast Fourier transform output along a non-final axis can be strided. Materialize a row-major contiguous MLX array before reading a host pointer; physical storage order can differ from logical tensor order.
- The MLX C application programming interface (MLX-C) v0.6.0 exposes real Fast Fourier transform and inverse real Fast Fourier transform without a public normalization argument. Bind those functions directly; the compatibility patch supplies backward normalization internally.
- Mark each successfully applied native patch by its content hash inside the generated source tree. A patch file containing multiple sequential commits cannot be classified reliably with one reverse dry run, while unconditional error suppression can hide partial application.
- Represent scalar Metal inputs as zero-dimensional MLX arrays; do not copy device values back to Rust merely to control a kernel loop.
- Preserve ownership around C vectors, arrays, kernel handles, and output handles. Performance work must not weaken memory safety.

## Graphics-processor kernel-panic evidence

- A full-resident Qwen3.6-35B-A3B-8bit run coincided with "completeMemory() prepare count underflow" @IOGPUMemory.cpp:550 on macOS 26.5.2. The inference worker held 38,426 MiB resident at the panic.
- This panic proves an IOGPU memory-bookkeeping failure, not its initiating cause. Do not attribute it to paging, cache eviction, a particular MLX operation, or memory exhaustion without a controlled reproduction.
- Metal's recommended maximum working-set size is guidance, not a safe request-admission boundary. Before each growth operation, project current active memory, exact persistent growth, and the observed transient high-water mark. Enforce stable and expected-peak limits; retain the equal recovery projection as diagnostic evidence for typed rollback and exact reclamation rather than forcing storage streaming before a failure occurs.
- Learn transient headroom from operation-local MLX peak samples instead of withholding a fixed multi-gigabyte block. Project rounded physical key-value slab growth rather than logical token growth.
- A completed prefill observation and a positive transient byte count are different facts. Record observation completion separately for adaptive request-growth projections; do not use either fact as permission to occupy reversible idle memory with expert weights.
- Carry the adaptive guard's measured transient high-water window into later request-start and injected-context admission. Post-request expert recovery may use idle capacity because the next similar request reclaims only the exact context and learned-transient deficit before forward execution.
- Track prefill and decode transient high-water windows independently. Multi-token prefill can route many unique one-expert pages, while one-token decode uses only top-K experts. Applying the prefill peak before every decode operation evicts safe one-expert entries and can turn the request into SSD-bound thrashing.
- Persistent prompt-cache restoration must consume one decoder layer at a time. After the allocation-free prefix lookup, reserve one restored-prefix copy so loaded blocks can coexist with growing live state; then drop each layer's source tensors after that layer materializes. Holding every block until one terminal evaluation duplicates the complete prefix and can exceed a near-disk-size ceiling even after expert admission admits the request.
- Run the same mutable resident-to-paged admission before every context-allocation boundary, including persistent prompt-cache reconstruction. Initial context plus publication workspace can fit beside complete experts while the loaded-prefix overlap does not; an immutable model validator can evict paged entries but cannot release the complete resident owner.
- Attribute expert bytes reclaimed for prompt-cache restoration separately from publication so request records distinguish reconstruction pressure from direct serialization pressure.
- Drop the loaded prompt-cache block owners before clearing the MLX allocator, then re-admit only the context tokens that remain after the restored prefix. Clearing while block owners are live cannot reclaim their allocations, while retaining the reconstruction-only expert ceiling makes the faster cache-hit path needlessly paged for the rest of generation.
- Project mixed full/sliding decoder memory as separate owners. Append-only capacity growth and bounded rotating-state growth remain persistent, while a multi-token rotating update temporarily owns `window + chunk - 1` chronological key/value rows. Combining that temporary workspace with learned transient high-water prevents a fitting stable cache from hiding an over-limit prefill peak.
- Request-start admission must reserve rotating temporary workspace for one executable prompt-processing chunk, not the complete prompt. Laguna executes 2,048-token chunks, so charging a 24,000-token rotating workspace can demote a fitting 39-layer resident owner. After that false demotion, generation fell from 45-50 tokens per second to 6-11 while 17 layers streamed from solid-state storage on every token. Persistent key/value growth still uses the complete context; only the temporary workspace is chunk-bounded.
- A live active-memory ceiling change must update the allocator-cache ceiling coherently. Lower the allocator cap to the smaller active ceiling when necessary, but retain the startup-resolved allocator cap and restore it when active capacity rises; otherwise a same-process MLX runtime can remain permanently reconfigured and reject later model or test initialization.
- A retry checkpoint must cover every mutable owner advanced inside an attempt, including decoder allocations, prompt cursor, and prompt-cache publication parent. Restore it before cleanup or expert reclamation, authorize at most one unchanged retry from typed allocation evidence, and then reduce the fixed prompt chunk deterministically so repeated pressure cannot create an unbounded retry loop.
- Treat an absent prompt-cache boundary file as valid when the decoder storage contract is sequence-only. Requiring a recurrent snapshot file for an empty boundary topology turns a successfully published key/value prefix into a fatal warm-cache miss; the contract’s `has_boundary_state` result must govern whether a boundary read is required.
- Prove paged model loading from a cold process with an MLX ceiling below the discovered safetensors payload, not only by loading resident and lowering the ceiling afterward. On-disk bytes are not an active-memory budget, but this acceptance boundary proves startup does not require simultaneous ownership of every routed expert and that generation can proceed through bounded page materialization.
- Carry prefill or decode phase explicitly through expert paging. A valid final prefill chunk can contain one token, so token count cannot select routed-page versus complete-layer behavior or choose the transient-memory evidence bucket.
- Count experts actually read from a page manifest, not experts selected by the router. Complete-layer prefill can read every expert even when one token routes to a strict subset; selected-expert counts understate solid-state-drive traffic.
- Require direct Metal input/output ranges to cover every destination tensor byte exactly. Bounds and non-overlap checks alone can leave uninitialized graphics-processor memory inside an otherwise valid MLX array and silently corrupt later matrix operations.
- Record execution mode, process footprint, wired memory, free memory, MLX memory counters, and the final submitted operation when testing large full-resident models.
- Treat throughput as invalid when the workload leaves insufficient operating-system headroom or destabilizes the graphics-processor driver.
- Never disable adaptive RAM growth protection in production. Raising the live MLX ceiling from 35 GB to 40 GB filled all 40 expert layers, left 36.83 GB active before a 41,725-token cached request, and was followed by an IOGPUMemory prepare-count-underflow kernel panic. Controlled benchmarks may disable protection only when they cannot expose the laptop to sustained high-memory inference.

## Durable rule

- Reuse the decode allocator observation already required for adaptive memory admission as live telemetry; a second MLX query or synchronization on the token path adds overhead without improving the measurement.

- A user-selected MLX memory ceiling must remain one authority: update the MLX wired, active, and allocator-cache process limits together, then update request admission, adaptive growth, and expert paging from that same exact byte cap. Decimal configuration gigabytes use 1,000,000,000 bytes.

- When lowering a live ceiling, compare the resident active snapshot plus derived request-execution headroom with the requested ceiling. A static resident snapshot fitting is insufficient when it leaves no room to serve. Demote the complete owner or evict retained expert payload first, synchronize the model graphics-processor stream, clear reclaimable allocator memory, and verify active bytes before lowering native MLX limits.

- When raising a live ceiling, change native Machine Learning framework for Apple silicon limits and the centralized Rust budget before attempting exact whole-model promotion. Publish only a complete candidate; remain paged when it does not fit, and restore both limits after a structural promotion failure.

- Publish the expert-topology snapshot produced by a live ceiling transition in the same acknowledgement as its memory counters and mode. Publishing only `resident`, `hybrid`, or `paged` leaves the prior layer counts visible and makes post-transition performance attribution describe two different runtime states.

When native MLX is slower than the Python reference, assume graph or kernel-path divergence first. Compare source, disable one reference optimization, inspect compiled feature gates, and profile evaluation before redesigning architecture.
## Preserve bounded child-process diagnostics at the supervisor boundary

When a model worker closes its protocol stream during startup, forwarding child stderr to the parent terminal is insufficient for a menu-launched application because that terminal may not exist. Retain a fixed-size stderr tail in the supervisor, report the child exit status and worker lifetime with the protocol-closure error, and include nested native-runtime causes in the worker's diagnostic text. This keeps failure logging bounded while making startup failures attributable from the persistent supervisor log alone.

## Durable model transfer

- Stream one model file at a time directly into hidden staging and resume from synchronized file lengths with Hypertext Transfer Protocol Range requests. This bounds transfer memory and avoids retransmitting verified progress after pause, failure, or restart.
- Benchmark transport protocols against the payload provider before changing them. Hypertext Transfer Protocol version 2 with adaptive receive windows can be slower than version 1.1 for a single large range stream, so protocol availability does not establish higher throughput.
- Keep high-frequency user-interface progress in process memory. Do not atomically rewrite and synchronize durable job metadata for each small payload increment; filesystem barriers serialize the network hot path. Persist at file completion, pause, failure, verification, and publication boundaries, then reconcile interrupted progress from synchronized staged-file lengths.
- Smooth displayed transfer rate across several observations. A one-second sample can land between content-delivery-network bursts and overstate a large model's remaining time even when sustained throughput is healthy.
- Attribute manifest fetch, each file transfer, verification, atomic publication, and discovery refresh separately. End-to-end download time alone cannot distinguish network, hashing, filesystem, and discovery costs.

## MTP sidecar expert-storage format vs layer-plan builder (2026-08-27)

MTP is resident-only. The expert pager must not include an MTP sparse layer, and SSD-paged sparse-expert serving stays target-only even when a valid MTP sidecar is present. Quantized MTP sidecars may store per-expert 2D tensors (`mtp.layers.0.mlp.experts.N.*`) instead of the 3D-packed `switch_mlp` layout the layer-plan builder expects; that storage difference is another reason not to page MTP experts, not a reason to extend SSD streaming to MTP.

A depth-three target-verification window is four activation rows. Stock one-token quantized matmul and a VERIFY_T-loop kernel both restream weights as the row count grows, so Metal decode falls from ~1.37x at depth one toward ~1.03x at depth three. A dedicated 4-bit four-row split-K matmul (K split across simdgroups, one column tile per threadgroup) is the verify-shaped kernel for that window; prefill and one-token decode stay on the existing routes. Numerics follow fp32 lane-strided accumulation, so gate on argmax agreement with the token-local path rather than bit identity.

## Sampled MTP at temperature 1 verifies distribution-correctly and still loses to target-only decode (2026-08-31)

- Measured on `Ornith-1.5-9B-vision-OptiQ-static-4.5bpw` (dense, depth-1 draft head), Romeo and Juliet fixture prompt, temperature 1.0, top-k 20, top-p 1.0, three locked seeds, both process orders: target-only sampled decode held 33.2–34.0 tokens per second while sampled speculative verification reached 22.7–24.1, a roughly thirty percent loss, in both orders.
- The acceptance counters explain the loss: 0–2 of roughly 62 proposed drafts accepted per 64-token run (under one percent). At temperature 1.0 with a top-k window the target sampling distribution is flatter than the draft head's own ranking, so `min(1, p/q)` acceptance collapses even when the draft head is well trained; the greedy acceptance advantage exists only at the highest-logit special case.
- Distributional equivalence is not the question: the sampled path emits exactly the target distribution (policy tests pin it), and the overhead is bounded. The verdict is throughput: speculative verification pays one extra proposal-plus-verify forward per window to save less than one token per window, and loses.
- Consequence: sampled multi-token prediction stays default-off and opt-in. A future artifact whose draft head tracks the target distribution at temperature 1 could re-measure; the measured acceptance rate is the single number that decides, and `mtp_effective_depth_total` times the observed acceptance rate bounds the achievable speedup.
- The three-window measurement also cost two real integration bugs found only by executing the path: a batched-row top-p mask that rejected multi-row sampling graphs and an acceptance coin encoding that returned the inverted Bernoulli case. Both were caught by a direct-MLX distribution test pinning the sampled probability ratio before any measurement claim was recorded.
