## Project overview

Astronomical is an Apple Silicon local model runner. The active architecture is a localhost Rust HTTP/SSE process plus one Rust worker subprocess; the worker owns MLX, artifact validation, model state, and chat, image, or embedding inference. Only one model is resident in GPU memory at a time; the supervisor hot-swaps to a different discovered model when a request changes identity or modality.

## Known gotchas

- Stable uses `~/.astronomical`, port 6732, and an explicitly promoted `~/Applications/Astronomical.app`; Development uses `~/.astronomical-dev`, port 6733, and `Astronomical Development.app`. Direct repository daemon execution and ordinary app builds default to Development. Config, logs, cache, ownership, lock, bundle identity, endpoint, and process cleanup stay instance-scoped; standard endpoints derive from the channel and are not user configuration. Model directories may be shared read-only. Never restore global process-name termination. Separate state cannot isolate shared GPU, wired memory, or SSD bandwidth, so real-model acceptance remains explicit and requires an exact model identifier advertised by Development.
- Tests and acceptance tools must never load active Stable configuration or derive writable paths beneath `~/.astronomical`; read model locations and policy from Development and keep mutable acceptance state in temporary `.astronomical-dev` directories. `scripts/check-test-channel-isolation.sh` enforces this.
- Product version comes from the Cargo workspace; bundles, `astronomicald --version`, `/v1/status`, the menu, and Observatory expose version, channel, build number, short commit, and dirty state. Stable packaging renders a timeless, badge-free `Astronomical.icns` and rejects dirty worktrees; Development adds a restrained `DEV` badge and records dirty state.
- The local API supports POST /v1/chat/completions (OpenAI chat chunks), POST /v1/responses (Copilot-compatible response items), POST /v1/images/generations (one lossless base64 PNG), and POST /v1/embeddings (one unit-norm vector per input). Chat and Responses share the autoregressive worker command; image and embeddings each have a separate typed command. Embeddings are synchronous single-shot: no step loop, no mid-request cancellation.
- Both generation endpoints resolve every thinking-control spelling through one shared resolver (#769): the numeric aliases `thinking_budget`/`thinking_token_budget`/`thinking_budget_tokens` plus the OpenRouter-style `reasoning.max_tokens`; level names `reasoning_effort` and `reasoning.effort` (minimal 1024 / low 2048 / medium 8192 / high 16384, xhigh and max clamp to high, off/none disable the channel); disable flags `reasoning.enabled:false`, flat `enable_thinking:false`, and `chat_template_kwargs.enable_thinking:false` (a disable maps to worker budget 0, which renders the thinking channel closed); and `reasoning.exclude`, which withholds reasoning deltas from the stream while usage still reports the reasoning token count. Explicit numbers beat level names, an explicit disable beats level names, and any disagreement (numbers vs numbers, levels vs levels, flags vs flags, disable vs positive budget) fails loudly as a typed `ThinkingControlsError`; the `reasoning` and `chat_template_kwargs` objects reject unknown subfields at deserialize time. pi sends only minimal/low/medium/high (never numeric unless the extension declares `supportsThinkingTokenBudget`). The resolved budget enforces in the worker exactly like numeric `thinking_budget` except on Laguna: Laguna renders thinking through its prompt template with no family-owned budget transition, so a positive budget is an enabling hint with no ceiling - the former hard rejection broke every reasoning_effort journey (#703/#704). A budget is a ceiling, so low levels on short prompts show no visible cap; the deterministic proof is `max_tokens` too small for the allowance rejected with `output-token budget N cannot fit the M-token thinking allowance` - reserve budget + transition (~24 tokens) + answer when scripting high levels on Qwen and K2. Copilot's `reasoning: {effort}` on Responses is now enforced, not ignored (#614).
- Models load lazily: startup launches an idle worker with no resident model; the supervisor discovers configured models for /v1/models, canonicalizes supported provider-prefixed IDs, sends SwapModel only when the first or a different REST generation request targets a discovered model, and waits for ModelSwapped before forwarding generation. Process-scoped telemetry and configuration events can precede that acknowledgement and must pass through the shared typed event handler; generation-scoped events remain protocol violations. A rejected load leaves the worker idle or preserves the previous model.
- Every instance scans `<instance-state>/models` before user-configured recursive roots; an absent automatic root is an empty Library, never created during resolution. Effective roots keep automatic-then-authored order and deduplicate exact lexically equal paths while `ResolvedRuntimeConfig.configured_model_directories` retains only authored roots; a Library model wins over the same public identity in an authored root; ambiguity among authored roots excludes those identities while unrelated models remain available. An unreadable authored root is skipped with a path-free `unavailable_model_directory` diagnostic and the menu retries daemon startup instead of sitting on a dead port. Status diagnostics identify model and one-based entry without exposing paths; organization/model trees are discoverable, hidden `.incomplete` staging is not. `model_directories` are recursive scan roots, not leaf directories, and ignored acceptance/measurement tests resolve exact IDs through Astronomical discovery, never an external model-manager directory.
- `registry/download_catalog.json` is an immutable release-authored catalog embedded into astronomicald and validated before listener binding, bounded to 1,000,000 bytes, 1,024 entries, and 256 bytes per display name; production intentionally permits empty entries. Schema 2 accepts executable Qwen3.5, Laguna, FLUX.2 Klein, ModernBERT embedding, and K2 Horizon MoVA stacked-affine entries with safe public Hugging Face identities, immutable lowercase 40-hex revisions, JavaScript-safe byte sizes, optional bounded executable-path selections, capability badges including `supports_embeddings`, and no unknown fields or case-insensitive collisions. `GET /v1/library/catalog` serves authored order and live readiness without worker dependency; Observatory `/library` retries interrupted loads, renders decimal SI sizes, and controls one daemon-owned download.
- One durable Library transfer uses `<instance-state>/models/.download-job.json`, serialized through `.download-job.lock`, with partials under `.incomplete/organization/model/`; job metadata is bounded, strict, atomically replaced, and reconciled from synchronized regular-file lengths after restart. Preflight derives disk checks from the models volume, persists only release-selected executable files with exact provider digests, and runs the DownloadExecutablePreflight identity gate that rejects unexecutable artifacts before any payload byte: it classifies config.json model_type through crates/config model_discovery, refuses recognized-but-non-executable families, and for Qwen3.5 validates context window, tokenizer presence, and that every weight-map shard exists in the manifest, surfacing public code `model_not_executable`. Small preflight Git files use bounded /raw/ endpoints (`fetch_bounded_repository_file`), not payload redirects; the `has_exact_manifest` resume path skips the gate. Transfer streams immutable file ranges into a bounded in-file assembler appending strictly at the contiguous prefix, each segment reading its own open-ended range from its recorded offset so staged length always equals received bytes regardless of completion order. Provider SHA-256 or Git-blob SHA-1 evidence is verified before staging is atomically renamed; publication writes provider identity and immutable revision provenance, and after rename readiness stays publishing until discovery refresh succeeds (restart retries it). A pre-existing destination is adopted only when every selected file matches provider digest evidence; mismatches stay untouched. A checksum failure truncates only the invalid file so Resume re-fetches it while retaining verified progress. Interrupted preflight, manifest, transfer, and verification states recover as paused. Cancel removes only validated hidden staging and the job document.
- `/v1/models` publishes maximum input and output tokens as independent capabilities under one shared context window; maximum input reserves one generation position and admission enforces prompt plus output budget. Never reject metadata merely because the two maxima cannot be used simultaneously. Limits are two-tier (#638): configured `limits.maximum_context_tokens` is advisory - advertised unchanged, crossing only logs a warning - and the artifact's native position count is the only hard rejection; the split lives in `qwen3_5/text/context_token_validation.rs`, each family's text processor, and the engine's `hard_maximum_position_count`.
- Chat, image, and embeddings share one serial bounded FIFO queue and one active-request permit; up to `GENERATION_QUEUE_DEPTH` wait, excess receive HTTP 429 `server_capacity`, and permits release immediately on cancellation or client disconnect.
- XPC code and packaging are deleted; the daemon discovers its sibling worker automatically. Packaged apps load `mlx.metallib` from `Contents/Resources/share/mlx/`; `~/Library/Caches/Astronomical/native-builds` is compile-time only and a cache wipe must not prevent a shipped app from starting. The supervisor must not depend on model-serving or runtime-integration; MLX belongs only in the worker, whose normal builds include direct-mlx; the supervisor resolves user configuration and sends worker-owned startup paths over typed IPC; the worker starts without a model directory and receives one only through SwapModel.
- IPC uses one length-delimited JSON frame per command or event with a 32 MiB cap matching HTTP transport; image bytes remain vectors internally, base64 on the wire. Oversized chat or image commands fail request-scoped without discarding the loaded worker. Chat text validation has no per-message or aggregate cap in REST or IPC - only the transport cap. Image completion stays private until a separate finalization event proves request-array release and allocator cleanup.
- Qwen3.5 admission, execution, and sampling read vocabulary and context limits from validated config. Initial admission projects resident experts with no routed-page reserve; if context does not fit it demotes the whole expert owner and reprojects with the model-derived largest routed top-K page; there is no fixed expert-paging headroom field. After an allocation-free persistent prompt-cache lookup, mutable admission also reserves one restored-prefix key/value payload because reconstruction temporarily owns both loaded blocks and concatenated live state, demoting complete resident experts before reading arrays when that overlap does not fit; restoration drops loaded block owners before allocator cleanup, then re-admits only context remaining after the restored prefix. Per-forward admission enforces exact persistent growth plus a transient reserve at the highest available specificity: exact execution context's high-water first, then a token-proportional estimate from same-phase observations, then the global maximum only for a phase with no evidence - the former global-maximum-only reserve charged one shape's transient to every shape and demoted fully resident owners whose own chunk needed a fraction of it (#623; the projection records the supplying level via `transient_reserve_source`). A second equal recovery window stays diagnostic and cannot preemptively demote or reclaim; typed allocation pressure restores the checkpoint, reclaims the exact deficit, and retries the unchanged chunk. Prefill capacity recovery classifies typed MLX errors from direct execution and Rust bounded expert loading, and both restore the request checkpoint before a request can be rejected.
- OpenCode MCP schemas use both `type: ["string", "null"]` and two-branch nullable anyOf including constrained integer branches; Copilot CLI adds two-branch non-null anyOf and canvas tools whose input property intentionally has no type; the Qwen3.5 output parser dynamically parses supported unions and truly untyped properties. A declared-tool property may declare any anyOf branch count - three-branch enum-like string parameters are accepted because argument parsing depends only on branch types, and branch count must never reject the whole thread (#736). Uniformly typed anyOf keeps its declared type; mixed branches parse dynamically; a rejected declaration names its tool and property. Closed `<tool_call>` envelopes fail open - unknown names, sloppy inner XML, and schema mismatches forward to the harness - while resource bounds and unclosed envelopes stay fatal. Do not restore Qwen undeclared-function model-visible correction injection; `ModelVisibleCorrection` remains only leftover renderer/test machinery. Thinking-enabled generation begins after a prompt-owned `<think>` prefix, so its parser must start in reasoning state rather than wait for the model to repeat that marker.
- Invalid model tool calls never fail closed: the parser fail-opens malformed or unknown tool-call names to the harness (its tool-not-found result is the model's correction signal); request validation requires only a non-empty name for assistant history tool calls - the strict portable grammar applies only to caller-declared `tools` definitions - and prompt rendering treats history tool calls as a fidelity path, rendering malformed arguments best-effort instead of stranding the request. Pinned by rest-contract tests (model-invented `r=bash` history round-trips) and the qwen3_5_hermetic prompt renderer test.
- Copilot CLI 1.0.73 discards text from valid BYOK `response.reasoning_text.delta` events, recording only an opaque reasoning item ID and rendering blank reasoning entries. For compatibility Astronomical exposes raw Qwen3.5 reasoning as plaintext summary_text through `response.reasoning_summary_text.delta/done` and completed reasoning summaries, and never emits plaintext as encrypted_content.
- Public stream failures retain four stable bounded codes: chat_invalid_request, chat_engine_busy, chat_malformed_model_output, chat_worker_unavailable; a pre-stream model rejection returns model_load_failed with the worker's cause chain instead of misreporting whole-worker unavailability. Keep messages actionable without exposing native errors or local paths.
- Completion IDs carry a process-instance namespace before the request counter so tool-call IDs stay distinct across daemon restarts; historical tool-call IDs are lifecycle-scoped - reuse valid only after the earlier call has a result, unresolved duplicates fail validation.
- `InferenceEngineError::InvalidRequest` is request-scoped at generation start, token advancement, and injected-token advancement: emit `WorkerEvent::Failed` and keep the loaded worker reusable. Truly fatal worker returns use a bounded Tokio runtime shutdown because Tokio stdin reads cannot be cancelled and must not leave a half-dead process retaining MLX memory.
- Automatic worker replacement, backoff, and policy are removed: a worker fault terminates the worker and reports plain unavailable, and public health has only loading, ready, and unavailable. Worker stderr is a bounded supervisor-owned diagnostic: when worker IPC closes the supervisor log records exit status, worker lifetime, and the newest 8 KiB of stderr so menu-launched failures retain their nested native cause.

## Conventions

- Everything is derived from the constitution `docs/north-star-product-vision.md`; read it as the source of truth.
- Keep `docs/performance-optimizations-lessons.md` updated with lessons relevant to LLM, VLM, and MLX APIs.
- Every command and test must emit a live progress indicator; never issue a silent command.
- Every test has a built-in timeout, max 120 seconds, except endurance/endurance-style tests and OOM reproductions. MLX/GPU acceptance journeys must never run in parallel (each loads weights into wired GPU memory, which can multiply demand past the physical limit and panic the machine). This is enforced structurally by `scripts/run-bounded-cargo-test.sh`, which rejects any ignored-test invocation asking for more than one thread and injects `--test-threads=1`; hermetic CPU-only tests may parallelize safely. Confirm no other Astronomical instance holds a resident model before starting a journey.
- Never hardwire a developer home directory, workstation path, local model path, local endpoint, or machine-specific hardware assumption into production code, tests, fixtures, artifacts, documentation, or GitHub content; resolve user-controlled locations through config, environment variables, platform-standard directories, command-line arguments, or explicit selection.
- Adapt to any laptop, any RAM size, and any GPU wired-memory limit; do not hardwire or optimize the codebase for this one dev machine.
- Fail forward: there are no downstream consumers, so do not add deprecation or compatibility shims.
- Keep code files near the ~500-line marker (prefer splitting over growing longer).
- End-user-facing file-size or memory values use decimal SI gigabytes (1 GB = 1,000,000,000 bytes); never show binary GiB values under a GB label.
- Prohibited terminology: the term "qualification" and every variant ("qualify", "qualified", "qualifier", etc.) is banned everywhere in code, comments, tests, scripts, docs, commit messages, and discourse. Describe the activity as running the acceptance journeys against the acceptance criteria.
- Performance logging and attribution must be present and switchable via config, capturing the start and end time of each operation to attribute slow-downs to specific code. Highest priority on the critical path: Model Loading, Prompt Processing, Tokenization, Disk Cache, Expert Paging, and token generation.
- The Romeo and Juliet fixture is the required source test input for LLMs; never use random text or tokens.
- All memory management code (policies, decisions, streaming, calculations) lives under `crates/model-serving/src/memory`.
- SSD model streaming tests should allocate RAM equal to ~50% of the model size on disk and report throughput for both prompt processing (tokens/s) and token generation (tokens/s).

## Entry points

- Before every requested commit run `scripts/verify-before-commit.sh`; never substitute `cargo test --workspace --all-targets`, which runs broad integration binaries serially. Run only immediately before committing/pushing; do this for unrelated changes only when confident they do not touch code or functionality (e.g. docs, version bumps, static-site, GitHub CI).
- Run `cargo fmt` (or equivalent) only at commit time, alongside the pre-commit verification, not during incremental work.
- `scripts/run-bounded-cargo-test.sh` is the gate for real-model journeys: it enforces the single-thread rule above (see Conventions) and is the only sanctioned runner for ignored MLX/GPU acceptance tests.
- `scripts/check-test-channel-isolation.sh` enforces that tests and acceptance tools never load active Stable configuration or derive writable paths beneath `~/.astronomical`; keep mutable acceptance state in temporary `.astronomical-dev` directories.
- `scripts/test-verify-before-commit-contract.sh` validates the commit-verification contract; the full run is bounded by `TEST_TIMEOUT_SECONDS` per step.
