Agent orientation map for non-obvious repository facts; this is not user-facing documentation or a changelog.

## Project overview

Astronomical is an Apple Silicon local model server. The active architecture is a localhost Rust HTTP/SSE process plus one Rust worker subprocess; the worker owns MLX, artifact validation, tokenization, model state, and generation. Only one model is resident in GPU memory at a time; the supervisor hot-swaps to a different model when a request targets a different discovered model. Obsolete paths not needed for real Qwen3.5 OpenAI-compatible SSE have been removed.

## Known gotchas

- The local API supports POST /v1/chat/completions for OpenAI chat chunks and POST /v1/responses for Copilot-compatible response items; both translate directly into the same worker Generate command.
- Models are loaded lazily: menu-app startup launches an idle worker with no resident model. The supervisor discovers configured models for /v1/models, canonicalizes supported provider-prefixed IDs, then sends SwapModel only when the first (or a different) REST generation request targets a discovered model. It waits for ModelSwapped before forwarding generation. A rejected model load leaves the worker idle or preserves the previous model so a later valid request can proceed.
- Generation requests are processed serially (one at a time) with a bounded FIFO queue. Up to GENERATION_QUEUE_DEPTH requests can wait while one is active; requests beyond the queue depth receive HTTP 429 with server_capacity. Queue permits are released immediately when a queued request is cancelled or its HTTP client disconnects.
- XPC code and packaging are deleted. The daemon discovers its sibling inference worker automatically.
- The supervisor must not depend on model-serving or runtime-integration; MLX belongs only in the worker.
- IPC uses one length-delimited JSON frame per command or event with a 32 MiB cap matching HTTP chat transport. There are no fragments, envelopes, protocol versions, sessions, public message/tool count caps, or smaller REST/IPC field byte caps; keep semantic validation and schema-depth checks instead.
- Chat text validation has no smaller per-message or aggregate-content cap in REST or IPC. The HTTP chat body has a 32 MiB transport cap.
- Qwen3.5 prompt admission, execution, and sampling read vocabulary and context limits from validated config. Initial admission reserves context-growing full-attention key/value state and the model-derived largest complete expert-layer page; there is no fixed expert-paging headroom field. After an allocation-free persistent prompt-cache lookup, admission also reserves one restored-prefix key/value payload because reconstruction temporarily owns both loaded blocks and concatenated live state. Restoration drops loaded block owners before allocator cleanup, then re-admits only the context remaining after the restored prefix; failed restoration resets request state, clears allocator memory, and repeats cold-context admission. Per-forward admission projects exact persistent growth against the configured ceiling and exact-context transient evidence against the one-percent allowed peak. A second same-context transient window only freezes expert-retention growth.
- Current OpenCode MCP schemas use both type: ["string", "null"] and two-branch nullable anyOf, including constrained integer branches. Copilot CLI also uses two-branch non-null anyOf such as string-or-array paths, plus interactive canvas tools whose input property intentionally has no type; the Qwen3.5 output parser dynamically parses those supported unions and truly untyped properties. Thinking-enabled generation begins after a prompt-owned <think> prefix, so its parser must start in reasoning state rather than waiting for the model to repeat that marker.
- Copilot CLI 1.0.73 discards text from valid bring-your-own-key response.reasoning_text.delta events and records only an opaque reasoning item ID, producing blank reasoning entries in its interface. For practical Copilot and industry compatibility, Astronomical exposes raw Qwen3.5 reasoning as plaintext summary_text through response.reasoning_summary_text.delta/done and completed reasoning summaries. It never emits plaintext as encrypted_content.
- Public stream failures retain four stable, bounded codes: chat_invalid_request, chat_engine_busy, chat_malformed_model_output, and chat_worker_unavailable. A pre-stream model rejection returns model_load_failed with the worker's cause chain instead of misreporting whole-worker unavailability. Keep human messages actionable without exposing native errors or local paths.
- OpenAI completion IDs carry a process-instance namespace before the request counter so tool-call IDs remain distinct across daemon restarts. Historical tool-call IDs are lifecycle-scoped: reuse is valid only after the earlier call has a result, while unresolved duplicates still fail validation.
- ProtocolWriter::close(self) intentionally consumes the writer so dropping owned child stdin delivers EOF on Unix.
- InferenceEngineError::InvalidRequest is request-scoped at generation start, token advancement, and injected-token advancement: emit WorkerEvent::Failed and keep the loaded worker reusable. Truly fatal worker returns use a bounded Tokio runtime shutdown because Tokio standard-input reads cannot be cancelled and must not leave a half-dead process retaining MLX memory.
- Normal worker builds include direct-mlx. The supervisor resolves user configuration and sends worker-owned startup paths over typed IPC. The inference worker starts without a model directory and receives a selected directory only through SwapModel.
- model_directories entries in the standard Astronomical configuration are recursive scan roots, not guaranteed leaf model directories. Ignored model qualification and measurement tests must resolve an exact model ID through Astronomical discovery and must not fall back to an external model-manager directory.
- Qwen3_5MoEArtifactValidator discovers executable model shards from the index, including a dedicated embedded-vision shard when present, accepts the fixed OptiQ vision sidecar separately, validates optional OptiQ metadata when present, ignores unrelated files, and does not full-hash model payloads.
- Dense model_type qwen3_5 checkpoints use the dedicated qwen3_5 public boundary and execute dense SwiGLU without router or expert allocation. Shallow discovery uses indexed physical visual weights, while loaded-worker image capability requires a complete validated embedded or separate vision tower; an embedded tower may share language shards or occupy a vision-only model shard. Metadata alone remains text-only.
- OptiQ metadata accepts the same affine widths as MLX (2, 3, 4, 5, 6, and 8 bits). Embedding and output-head measurements are optional, but must match config when present.
- The worker process RSS sampler, hardcoded launch-memory envelope, and heartbeat watchdog layers are gone. Model loading has a 60-second timeout; cancellation acknowledgement has a separate 60-second bound because one large MLX prefill chunk can legitimately outlive the 3-second process-shutdown grace period.
- The inference worker resolves one positive MLX wired-memory ceiling at startup. A positive iogpu.wired_limit_mb value is used directly; zero resolves the macOS default once through MLX device information. That value is the only memory ceiling for MLX limits, request admission, and expert paging. maximum_mlx_memory_gb is an optional decimal-SI user ceiling in config.json. A live change uses PUT /v1/config/maximum-mlx-memory; an active generation queues only the newest valid cap and applies it before the next request. Status exposes machine, effective, minimum, configured, pending, and error state. Request completion and cancellation clear reclaimable allocator state. Replacement-model loading also clears the process-global allocator pool after the prior model is dropped and before replacement weights load. Missing or malformed sysctl output fails startup. Hourly file diagnostics use a 1,024-line lossy queue so slow storage cannot grow memory or stall inference.
- The macOS menu keeps successful maximum-model-RAM feedback visible until status confirms the requested effective ceiling with no pending update, then clears it after one second. Queued applications remain visible until they take effect, and late worker rejections become failure feedback.
- The explicit scripts/test-mlx-memory-contracts.sh layer runs native MLX allocator contracts, direct Rust MLX-C contracts, and the required Qwen3.6-35B-A3B-8bit to Qwen3.6-35B-A3B-oQ4e-mtp lifecycle in serial isolated processes. It waits five seconds for Metal after model teardown before native allocation checks. The pinned native allocator rejects any new, reused, or host-backed allocation that would cross the configured ceiling plus one percent without changing active or peak counters. MLX allocator policy is process-global, so do not combine its tests with parallel GPU qualification. Completed model load can retain tiny graph bookkeeping, so compare cache relationally there; request-finalization cleanup must report zero cache with live model residency.
- Per-prefill-chunk allocator cleanup must synchronize the model-owned MLX graphics-processor stream first. The Metal allocator releases cached buffers without synchronizing submitted evaluation or direct Metal input/output work.
- The native MLX build uses runtime Metal kernel compilation so capable Apple GPUs receive Metal 4 matrix kernels; first-use compilation is cold-start work and later processes reuse the system cache.
- macOS can reject a linker-signed nested bundle executable with an invalid code-signature page even when static bundle verification passes. The app assembler must explicitly ad-hoc sign every Contents/MacOS executable before signing the enclosing bundle.
- The SwiftPM menu executable must enter through a SwiftUI App with @NSApplicationDelegateAdaptor. Marking the NSApplicationDelegate class itself as @main compiles and leaves a process running, but its launch callbacks do not run in the packaged app, so no status item or owned daemon appears. Keep regular activation until the status item registers, then switch to accessory mode on the next main-loop turn.
- UI values labeled GB use decimal SI units (1 GB = 1,000,000,000 bytes). Binary values must use the explicit GiB label; do not use ByteCountFormatter.CountStyle.memory, which applies binary scaling while producing labels such as GB.
- prefill-chunck-size-optimizer is an internal model-serving package for ask/tell one-dimensional online chunk tuning. Fixed mode requires positive fixed_prefill_chunck_tokens whether the optimizer setting is false or omitted. Explicit optimized mode derives 128-token doubling candidates through the validated model maximum, including that exact maximum when it is not a power of two, and persists observations by context bucket. Affine model weights accept the MLX-supported 2-, 3-, 4-, 5-, 6-, and 8-bit widths with group sizes 32, 64, or 128. The pinned MLX split-K patch caps row-count influence after 64 row tiles so equivalent 2,048-token and 4,096-token quantized projections retain one reduction topology. Mixture-of-experts assignments are sorted at 64 or more assignments before gathered quantized matrix multiplication. A custom Metal weighted-sum kernel consumes sorted outputs directly instead of restoring the expanded token/top-k tensor.
- The model retains shapeless MLX-C compilations for mixture-of-experts SwiGLU plus multi-token prefill-only attention gating, precise gated normalization, gated-delta decay, and sparse/shared expert combination. Shapeless callbacks must use scalar broadcast constants rather than input-shaped constants, which freeze the first traced token shape. One-token decode deliberately keeps the prior paths. The sorted-expert weighted-sum and gated-delta Metal kernel owners are retained with the model. mlx_closure_new() returning a null context is the valid pre-compilation output placeholder, not an allocation failure.
- Sparse mixture-of-experts residency is always automatic. Every sparse model owns ExpertPager-backed selected-expert weights, while maximum_mlx_memory_gb is the only user memory control. Startup prewarms complete layers only while they fit the live ceiling. Pressure evicts partial pages before complete layers, synchronizes the graphics-processor stream, clears released allocator storage, and resamples before reducing prompt-processing work. Resident and paged are observed outcomes, not configuration modes.
- The worker reports expert residency transitions independently from generated output. /v1/status retains expert_memory_mode as resident, paged, or null. Model readiness also reports expert_storage_format as standard_safetensors or astronomical_aligned; the menu labels these Standard and Astronomical Optimized under Expert storage. The menu flashes only actual resident/paged transitions.
- The menu derives cumulative session prompt reuse from completed-request prompt and reused-token totals; those totals survive model swaps and reset with the supervisor process. Its stacked MLX memory snapshot reconciles tracked expert, model-core, and request-context payload against measured active memory, assigns the remainder to runtime work, and derives available bytes from the machine-specific MLX ceiling. MLX has no allocator ownership tags, so never present the tracked categories as independently measured physical allocations.
- Do not replace bounded expert reads with typed memory-mapped MLX arrays without validating source alignment. Qwen3.6 packed UInt32 expert payloads can start at only two-byte alignment, and a GPU operation over such a typed view reads the wrong bytes; the bounded reader intentionally materializes aligned MLX storage.
- Bounded expert-reader cursor operations remain mutex-protected, but positional reads use immutable interval mappings and independent file offsets. The pinned MLX generic input/output pool uses half the logical processors clamped to 4–8 workers; keep this as one small native patch rather than adding a Rust scheduler or configuration layer.
- Two ignored one-layer tests measure the lowest practical expert data-plane boundary: bounded or direct Metal loading followed immediately by the same real gather-QMM operations. cargo measure-ornith-generation-expert-data-plane measures one token with eight routed assignments. cargo measure-ornith-prompt-processing-expert-data-plane measures one 2,048-token prompt chunk with 16,384 routed assignments and all 256 experts. They prewarm both paths, copy results to the host only after timing for exact parity, stream progress, and never enter REST, worker, or request orchestration.
- The oQ4e aligned-range diagnostic uses a configured decimal 10 GB MLX limit and compares legacy singleton ranges with adjacent-run coalescing against the same complete affine layer. It remains diagnostic; cargo measure-oq4e-10gb-representative-coalescing is the production-path qualification with 1,024 input tokens and 512 generated tokens. Inspect exact stable and peak bytes because the pinned allocator permits only the one-percent transient allowance above the configured ceiling.
- astronomical-model-preparer is the only production preparation entry point. It operates on one already-downloaded model directory, reports decimal GB disk requirements, requires interactive consent unless --yes is present, supports read-only --dry-run and explicit --replace, locks by exact revision, resumes validated staging layers, validates source payload parity, and atomically publishes only a complete format-version-2 revision. It never downloads models or runs automatically during model load, application launch, or validation.
- ExpertPager discovers tensor-major packs under .astronomical-aligned-expert-packs followed by the exact model revision, validates the complete revision and every source descriptor at startup, and submits selected ranges through native Metal input/output before the unchanged gather-QMM path. Activation is all-or-nothing; a missing, incomplete, stale, or invalid optional revision emits one warning and keeps every layer on bounded safetensors. The uniform Ornith 8-bit checkpoint has 40 aligned layers totaling 34.23 GB.
- The standalone C++ Metal input/output contracts run through scripts/test-native-metal-expert-loader.sh contracts. They cover native range validation, event ordering, repeated transaction cleanup, and immediate graphics-processor consumption. Performance measurement remains in the one-layer gather-QMM tests rather than a second native benchmark parser.
- Decode keeps sampling on the graphics processor and submits one token ahead with mlx_async_eval. Full-attention key-value storage grows in fixed 256-token steps; do not restore per-token host sampling or key-value concatenation.
- Real process/MLX/HTTP Qwen3.5 qualification is isolated behind the model-artifact-qualification inference-worker feature and an ignored test; normal workspace tests neither compile nor run that qualification module.
- The performance-measurement feature gates the model-artifact measurements and model_persistent_prompt_cache_warmup ignored tests. The artifact measurement covers cold throughput; the warmup test launches two worker processes sharing one SSD prompt cache and asserts the second restores cached blocks.
- Four in-process prefill_chunck_tokens sweep tests (1024/2048/4096/8192) share the same feature gate and are #[ignore]'d; they inject a Qwen3_5MoEPrefillChunckSizer through run_configured_worker_with_prefill_chunck_sizer_override over duplex pipes rather than spawning a subprocess, so they do not report peak physical footprint.
- Persistent Qwen3.5 prompt cache is always SSD-backed under the standard Astronomical configuration directory with a default 50 GB global ceiling across every model and revision. prompt_cache_max_size_gb overrides that decimal capacity. Each model retains an isolated model-and-revision subdirectory via PromptCacheConfig::for_model(). All SSD-backed cache implementation lives under crates/model-serving/src/persistent_cache/: state files, projected visual embeddings, safetensors validation, disk writes and reads, scanning, quota, indexing, retention, and counters. Qwen owns only typed layout construction, state conversion, image planning, model execution, and engine decisions. Cache contents are disposable local artifacts with no backward compatibility or migration support; bump the prompt-cache format version when serialized model-state semantics change, and clear the cache root when immediate disk reclamation is needed. PersistentPromptCacheDiskStore stores 2,048-token sequence-state files under kv_blocks/, GatedDeltaNet boundary snapshots under recurrent_snapshots/, and final BF16 projected image embeddings. Global eviction scans without following symlinks and deletes oldest-written files first, using the full path as a deterministic tie-breaker. File cleanup deletes or confirms absence before untracking; other deletion failures remain tracked and return a typed error. Snapshot-aware lookup restores only to a recurrent-consistent boundary. Failures fall back to cold prefill.
- Persistent prompt-cache captures serialize on the sole Machine Learning framework for Apple silicon owner thread, then enqueue only ordinary bytes to a 256 MB bounded filesystem queue. The writer is uncapped and uses device and operating-system throughput. The queue drops further captures when full, preserves atomic temporary-file publication, and abandons queued optimization work after a bounded shutdown wait.
- Adaptive RAM growth guarding is always enabled in production configuration. Direct engine construction may still disable it for controlled tests and benchmarks.
- performance_attribution_enabled defaults to false and writes worker-local aggregate model-loading and generation reports to ~/.astronomical/logs/performance-attribution.jsonl when enabled. The disabled path has no timing or writer allocation; changing it requires worker replacement. The enabled writer reopens a missing or replaced log path at the next report, so external rotation does not require an application restart. Report timings distinguish graph construction, asynchronous submission, synchronization waits, complete forward memory snapshots, and outer prefill, decode, attention, and multilayer-perceptron spans. Outer spans are excluded from the detailed attributed-duration sum because they overlap leaf operations. Paged reports also include exact bounded-reader solid-state-drive call count, successful bytes, summed worker read time, maximum single-read latency, and failures. Summed read time can exceed synchronization wall time because MLX input/output workers run concurrently.
- mtp_enabled is an explicit false-by-default user config field and must remain disabled by default until the representative parity and throughput release gate passes with approximately 1,000 input tokens and at least 512 generated tokens. Changing it requires worker replacement because runtime state depends on the loaded artifact. Supervisor status exposes both the preference and mtp_runtime_state. Valid artifacts with no MTP inventory report target_only, invalid MTP inventory reports unavailable with a bounded reason, and compatible MTP weights report active after binding. The native MTP decode path is depth-one and greedy-only: it admits exact rounded MTP plus target growth before drafting, verifies current plus draft in one target window, queues an accepted draft already present in target state, and keeps sampled requests target-only so MTP proposal randomness cannot perturb output distribution. Do not infer this setting or runtime state from sidecar presence, model names, shard counts, or local artifact paths.
- Automatic worker replacement/backoff/restart-budget policy is gone. On a worker fault, the supervisor terminates the worker and reports plain unavailable; public health has only loading, ready, and unavailable.
- Old split-out crate skeletons crates/supervisor-control, crates/native-bridge, and crates/model-artifacts are gone; do not resurrect them for the active path.
- Native archive bootstrap still SHA-256-verifies downloaded MLX source archives; that is separate from model-payload startup validation.
- Native patches pass through crates/runtime-integration/native/apply_patch_if_needed.cmake, which records a content-hash marker after clean application and rejects partial/conflicting state. When migrating an older generated tree without markers or changing a patch in place, remove only its generated mlx-c-runtime-build directory and rebuild from the verified archive. Do not suppress patch failures.

## Conventions

- Follow .github/instructions/rust.instructions.md for Rust and keep code Java-readable.
- Use CARGO_BUILD_JOBS="$(sysctl -n hw.logicalcpu)" for non-trivial Cargo verification on macOS.
- Classify tests by the highest external dependency needed to prove their contract: hermetic, rest_api, direct_mlx, mlx_memory_contract, model_artifact_qualification, persistent_prompt_cache_qualification, performance_measurement, macos_menu_contract, native_metal_contract, or structural_guard. Do not create a new test binary only to express a semantic category; preserve the existing execution boundary when it is the more expensive dependency.
- Run Rust tests through Cargo aliases except scripts/test-direct-mlx.sh and scripts/test-mlx-memory-contracts.sh, which run isolated MLX targets with live progress and individual 120-second guards. Those scripts and commit verification pass Cargo verbose output so the active sccache rustc command remains visible during long compilation.
- Cargo aliases select hermetic, REST API, model-artifact qualification, persistent prompt-cache qualification, performance measurement, and parity targets by execution boundary. Slow and ignored lanes remain explicit.
- Keep production Rust sources at or below the 500-line principle; move a cohesive owner to a direct sibling instead of enlarging a near-limit file.
- The tracked Git pre-commit hook checks staged human-authored Rust, Python, shell, Swift, C-family, Metal, JavaScript, and TypeScript source including tests. It blocks files above 600 lines, reads the index rather than the worktree, and exempts only an explicit first-line generated marker. Run scripts/install-git-hooks.sh after cloning to activate it. The separate scripts/check-source-size.sh production-Rust scan warns at 501–550 lines and fails at 551+; run scripts/test-source-size-check.sh to verify both guards.
- Do not add crates, facades, registries, launchers, managers, actors, adapters, or services unless they remove code from the active path.
- Open Brain provenance is project-scoped: every Astronomical recall and structured memory write must declare project_id as astronomical. Store only durable decisions, verified evidence, explicit user preferences, unresolved blockers, and outcome summaries; do not store file inventories, transient test output, local-machine details, or completed implementation logs. Project-scoped recall can include unscoped legacy thoughts, so use only records whose returned project ID is astronomical unless separately verified. Before broad memory cleanup, confirm the candidate records belong to Astronomical.
- Markdown docs should not hard-wrap prose.

## Entry points

- Inspect the machine GPU wired-memory ceiling: sysctl -n iogpu.wired_limit_mb.
- Format: cargo fmt --all.
- Fast hermetic tests: cargo test-hermetic.
- Public REST/API tests: cargo test-rest-api.
- Direct MLX contracts: scripts/test-direct-mlx.sh.
- Explicit MLX memory-contract qualification: scripts/test-mlx-memory-contracts.sh (requires both named local checkpoints and fails if either is absent).
- Production Rust source-size guard: scripts/check-source-size.sh; structural guard test: scripts/test-source-size-check.sh.
- Install the tracked staged-source pre-commit guard: scripts/install-git-hooks.sh.
- Model-artifact qualification: configure model_directories in the standard Astronomical configuration file, then run cargo qualify-model-artifacts.
- Deployment REST liveness: cargo qualify-deployed-model-rest-liveness runs one release-model worker through four public TCP requests on one process: long Chat with representative tools, short Chat, reused long Chat, then reused long Responses. It requires clean SSE completion and a ready worker afterward.
- Performance measurement support: cargo test-performance-measurement-support; slow model-artifact measurements run one command at a time with cargo measure-model-artifact-summary, cargo measure-persistent-prompt-cache-warmup, or cargo measure-model-artifact-prefill-2048.
- Qwen3.6 automatic cold/warm attribution benchmark: cargo measure-model-artifact-performance-attribution; it is ignored by default, uses an internal 120-second timeout, and skips when the exact local checkpoint is absent.
- One-layer generation expert data-plane measurement: cargo measure-ornith-generation-expert-data-plane.
- One-layer prompt-processing expert data-plane measurement: cargo measure-ornith-prompt-processing-expert-data-plane.
- oQ4e 10 GB aligned-range diagnostic: cargo measure-oq4e-10gb-aligned-range-coalescing.
- oQ4e 10 GB representative aligned-paging measurement: cargo measure-oq4e-10gb-representative-coalescing.
- Inspect one already-downloaded model without mutation: astronomical-model-preparer --model-directory PATH --dry-run. Prepare only after informed consent with astronomical-model-preparer --model-directory PATH, or use --yes for explicit non-interactive confirmation. Use --replace only to replace an invalid generated revision. Reload that model after preparation so startup can validate and activate the complete pack set.
- Standalone native Metal input/output contracts: scripts/test-native-metal-expert-loader.sh contracts. The command streams progress and enforces a 120-second timeout.
- Before a requested commit or push, run scripts/verify-before-commit.sh for bounded formatting plus filtered hermetic and REST API verification; never substitute the broad serial Cargo all-target test command.
- Regenerate locked Rust dependency notices with scripts/generate-rust-dependency-notices.sh. Use its --check mode to verify the checked-in artifact is current.
- Build real binaries: CARGO_BUILD_JOBS="$(sysctl -n hw.logicalcpu)" cargo build -p astronomical-inference-worker --bin astronomical-inference-worker -p astronomical-supervisor --bin astronomicald.
- macOS menu contract tests: scripts/test-macos-menu-contracts.sh runs SwiftPM with live progress and a 120-second process timeout.
- Build and assemble the macOS menu bar app: scripts/make-astronomical-app.sh builds Rust daemon/worker binaries plus the Swift menu package, then produces target/astronomical-macos-release/Astronomical.app.
- Run real Qwen3.5 daemon: put model directories in ~/.astronomical/config.json, then run CARGO_BUILD_JOBS="$(sysctl -n hw.logicalcpu)" cargo build -p astronomical-inference-worker --bin astronomical-inference-worker -p astronomical-supervisor --bin astronomicald && cargo run -p astronomical-supervisor --bin astronomicald.
- Open the Observatory web console: run astronomicald, then open http://localhost:<bound-port>/ in a browser. The console polls /v1/status, /v1/cache/stats, and /v1/models every second and streams chat through /v1/chat/completions. No separate build step or frontend process.
- Model directories and prompt-cache capacity come from the standard Astronomical configuration file. Test workers use temporary configuration homes and typed IPC startup configuration instead of shell launchers.

## What to verify

- Whether the active OpenAI SSE path still streams real Qwen3.5 output.
