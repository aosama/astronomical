## Project overview

Astronomical is an Apple Silicon local model runner. The active architecture is a localhost Rust HTTP/SSE process plus one Rust worker subprocess; the worker owns MLX, artifact validation, model state, and chat, image, or embedding inference. Only one model is resident in GPU memory at a time; the supervisor hot-swaps to a different discovered model when a request changes identity or modality.

## Known gotchas

- Stable uses `~/.astronomical`, port 6732, and an explicitly promoted `~/Applications/Astronomical.app`. Development uses `~/.astronomical-dev`, port 6733, and `Astronomical Development.app`. Direct repository daemon execution and ordinary app builds default to Development. Config, logs, cache, ownership, lock, bundle identity, endpoint, and process cleanup remain instance-scoped; standard endpoints derive from the channel and are not user configuration. Model directories may be shared read-only. Never restore global process-name termination. Separate state cannot isolate shared GPU, wired memory, or SSD bandwidth, so real-model acceptance remains explicit and requires an exact model identifier advertised by Development.
- Tests and acceptance tools must never load the active Stable configuration or derive writable paths beneath `~/.astronomical`. Read model locations and policy from Development, and keep mutable acceptance state in temporary `.astronomical-dev` directories. `scripts/check-test-channel-isolation.sh` enforces this boundary.
- Product version comes from the Cargo workspace. App bundles, `astronomicald --version`, `/v1/status`, the menu, and Observatory expose semantic version, channel, build number, short commit, and dirty state. Stable packaging renders a timeless, badge-free `Astronomical.icns` and rejects dirty worktrees; Development uses the same product artwork with a restrained `DEV` badge and records dirty state.
- The local API supports POST /v1/chat/completions for OpenAI chat chunks, POST /v1/responses for Copilot-compatible response items, POST /v1/images/generations for one lossless base64 PNG, and POST /v1/embeddings for one unit-norm vector per input. Chat and Responses share the autoregressive worker command; image generation and embeddings each have a separate typed command. Embeddings are synchronous single-shot: no step loop and no mid-request cancellation.
- ChatGPT-style clients that set a thinking level (pi sends only `reasoning_effort: "minimal" | "low" | "medium" | "high"`; it never sends a numeric budget unless the provider extension declares `supportsThinkingTokenBudget`) get it mapped to a token budget at the REST contract (minimal 1024 / low 2048 / medium 8192 / high 16384, xhigh→high, an explicit numeric budget spelling wins, unknown labels fail loudly). The mapped budget then enforces in the worker exactly like a numeric `thinking_budget`, except on Laguna: Laguna renders thinking through its prompt template with no family-owned budget transition, so a positive budget acts as a thinking-enabling hint and carries no ceiling (#703, PR #704 — the former hard rejection `positive thinking budgets are not supported by Laguna generation` broke every reasoning_effort journey). Because a budget is a ceiling on enforcing families, low levels on short prompts show no visible cap; the deterministic proof is that `max_tokens` too small for the allowance is rejected with `output-token budget N cannot fit the M-token thinking allowance` — reserve budget + transition (~24 tokens) + visible answer when scripting high levels on Qwen and K2. The Responses surface's `reasoning: {effort}` remains an opaque ignored value (#614).
- Models are loaded lazily: menu-app startup launches an idle worker with no resident model. The supervisor discovers configured models for /v1/models, canonicalizes supported provider-prefixed IDs, then sends SwapModel only when the first (or a different) REST generation request targets a discovered model. It waits for ModelSwapped before forwarding generation. Process-scoped telemetry and configuration events can precede that acknowledgement and must pass through the shared typed event handler; generation-scoped events remain protocol violations. A rejected model load leaves the worker idle or preserves the previous model so a later valid request can proceed.
- Every instance automatically scans `<instance-state>/models` before user-configured recursive roots. An absent automatic root is an empty Library and is not created during resolution. Effective roots preserve automatic-then-authored order and deduplicate exact lexically equal paths, while `ResolvedRuntimeConfig.configured_model_directories` retains only user-authored roots. A Library model wins over the same public identity in an authored root. Ambiguous identities among authored roots are excluded while unrelated models remain available. An unreadable authored root is skipped with a path-free `unavailable_model_directory` diagnostic so remaining models still start; the menu retries daemon startup instead of sitting on a dead port. Bounded status diagnostics identify the model and one-based configuration entries without exposing paths. Existing organization/model trees are discoverable; hidden `.incomplete` staging remains undiscoverable.
- `registry/download_catalog.json` is an immutable release-authored catalog embedded into astronomicald and validated before listener binding. Catalog metadata is bounded to 1,000,000 bytes, 1,024 entries, and 256 bytes per display name. Schema version 2 accepts executable Qwen3.5, Laguna, FLUX.2 Klein, ModernBERT embedding, and K2 Horizon MoVA stacked-affine entries with safe public Hugging Face identities, immutable lowercase 40-character hexadecimal revisions, JavaScript-safe byte sizes, optional bounded executable-path selections, capability badges including `supports_embeddings`, and no unknown fields or case-insensitive collisions. `GET /v1/library/catalog` serves authored order and live readiness without worker dependency. Observatory `/library` retries interrupted catalog loads, renders decimal SI sizes, and controls one daemon-owned download.
- One durable Library transfer uses `<instance-state>/models/.download-job.json`; independent store instances serialize mutations through `.download-job.lock`, and partial files remain under `.incomplete/organization/model/`. Job metadata is bounded, strict, atomically replaced, and reconciled from synchronized regular-file lengths after restart. Manifest preflight derives both disk checks from this models volume and persists only release-selected executable files with exact provider digests. Payload transfer streams each immutable file range through a bounded in-file assembler that appends strictly at the contiguous prefix, with pending files decomposed into fixed absolute segments and their first segments launched round-wise within a bounded eight-request window so the largest file starts first and no single shard straggles at the tail; each segment reads its own open-ended range from its recorded start offset, so staged lengths keep equaling received bytes no matter which segment finishes first. Quarter-second user-interface progress stays in memory so synchronized job rewrites do not throttle the network path. File completion, pause, failure, verification, and publication remain durable boundaries. Provider SHA-256 or Git-blob SHA-1 evidence is verified before staging is atomically renamed. Publication writes strict provider identity and immutable revision provenance so ordinary discovery preserves readiness after daemon restart. A pre-existing destination is adopted only when every selected file matches provider digest evidence; mismatches remain untouched. A checksum failure truncates only the invalid file so Resume re-fetches it while retaining verified progress. Interrupted preflight, manifest, transfer, and verification states recover as paused. An executable-identity gate inside manifest preflight (DownloadExecutablePreflight) rejects unexecutable artifacts before any payload byte is requested: it classifies config.json model_type through crates/config model_discovery, refuses recognized-but-non-executable families, and for Qwen3.5 validates context window, tokenizer presence, and that every weight-map shard exists in the manifest; failures surface the public error code model_not_executable. Small preflight Git files are read through bounded /raw/ origin endpoints (fetch_bounded_repository_file) rather than payload redirects; the has_exact_manifest resume path skips the gate because the manifest was already validated. Cancel removes only validated hidden staging and the job document. After rename, readiness remains publishing until discovery refresh succeeds, and restart retries that refresh.
- `/v1/models` publishes maximum input and output token counts as independent capabilities under one shared context window. The maximum input reserves one generation position; request admission enforces the selected prompt plus output budget. Never reject metadata merely because the two independent maxima cannot be used simultaneously.
- Chat, image, and embeddings requests share one serial bounded FIFO queue and one active-request permit. Up to GENERATION_QUEUE_DEPTH requests can wait; excess requests receive HTTP 429 with server_capacity. Queue permits are released immediately when a queued request is cancelled or its HTTP client disconnects.
- XPC code and packaging are deleted. The daemon discovers its sibling inference worker automatically.
- Packaged apps load `mlx.metallib` from `Contents/Resources/share/mlx/`. `~/Library/Caches/Astronomical/native-builds` is the compile-time native store only; a cache wipe must not prevent a shipped app from starting.
- The supervisor must not depend on model-serving or runtime-integration; MLX belongs only in the worker.
- IPC uses one length-delimited JSON frame per command or event with a 32 MiB cap matching HTTP transport. Image bytes remain vectors internally and use base64 on the JSON wire. Oversized chat or image commands fail request-scoped without discarding the loaded worker. Image completion remains private until a separate finalization event proves request-array release and allocator cleanup.
- Chat text validation has no smaller per-message or aggregate-content cap in REST or IPC. The HTTP chat body has a 32 MiB transport cap.
- Qwen3.5 prompt admission, execution, and sampling read vocabulary and context limits from validated config. Initial admission projects resident experts with no routed-page reserve; if context does not fit, it demotes the whole expert owner and reprojects with the model-derived largest routed top-K page. There is no fixed expert-paging headroom field. After an allocation-free persistent prompt-cache lookup, mutable admission also reserves one restored-prefix key/value payload because reconstruction temporarily owns both loaded blocks and concatenated live state; it demotes complete resident experts before reading arrays when that overlap does not fit. Restoration drops loaded block owners before allocator cleanup, then re-admits only the context remaining after the restored prefix. Per-forward admission enforces exact persistent growth plus a transient reserve resolved at the highest available specificity: the exact execution context's high-water first, then a token-proportional estimate from same-phase observations, then the global maximum only for a phase with no evidence (issue #623 — the former global-maximum-only reserve charged one shape's transient to every other shape and demoted fully resident expert owners whose own chunk needed a fraction of it; the projection records which level supplied the reserve via `transient_reserve_source`). A second equal recovery window remains diagnostic and cannot preemptively demote or reclaim experts; typed allocation pressure restores the checkpoint, reclaims the exact deficit, and retries the unchanged chunk.
- Current OpenCode MCP schemas use both type: ["string", "null"] and two-branch nullable anyOf, including constrained integer branches. Copilot CLI also uses two-branch non-null anyOf such as string-or-array paths, plus interactive canvas tools whose input property intentionally has no type; the Qwen3.5 output parser dynamically parses those supported unions and truly untyped properties. Closed `<tool_call>` envelopes fail open: unknown names, sloppy inner XML, and schema mismatches forward to the harness. Resource bounds and unclosed envelopes stay fatal. Do not restore Qwen undeclared-function model-visible correction injection; `ModelVisibleCorrection` remains only as leftover renderer/test machinery. Thinking-enabled generation begins after a prompt-owned <think> prefix, so its parser must start in reasoning state rather than waiting for the model to repeat that marker.
- Copilot CLI 1.0.73 discards text from valid bring-your-own-key response.reasoning_text.delta events and records only an opaque reasoning item ID, producing blank reasoning entries in its interface. For practical Copilot and industry compatibility, Astronomical exposes raw Qwen3.5 reasoning as plaintext summary_text through response.reasoning_summary_text.delta/done and completed reasoning summaries. It never emits plaintext as encrypted_content.
- Public stream failures retain four stable, bounded codes: chat_invalid_request, chat_engine_busy, chat_malformed_model_output, and chat_worker_unavailable. A pre-stream model rejection returns model_load_failed with the worker's cause chain instead of misreporting whole-worker unavailability. Keep human messages actionable without exposing native errors or local paths.
- Invalid model tool calls never fail closed. The output parser fail-opens malformed or unknown tool-call names to the harness (the harness's tool-not-found result is the model's correction signal); chat request validation requires only a non-empty name for assistant history tool calls — the strict portable grammar applies only to caller-declared `tools` definitions — and prompt rendering treats history tool calls as a fidelity path, rendering malformed arguments best-effort instead of stranding the request. Pinned by rest-contract tests (model-invented `r=bash` history round-trips; definitions keep the grammar) and the qwen3_5_hermetic prompt renderer test.
- OpenAI completion IDs carry a process-instance namespace before the request counter so tool-call IDs remain distinct across daemon restarts. Historical tool-call IDs are lifecycle-scoped: reuse is valid only after the earlier call has a result, while unresolved duplicates still fail validation.
- InferenceEngineError::InvalidRequest is request-scoped at generation start, token advancement, and injected-token advancement: emit WorkerEvent::Failed and keep the loaded worker reusable. Truly fatal worker returns use a bounded Tokio runtime shutdown because Tokio standard-input reads cannot be cancelled and must not leave a half-dead process retaining MLX memory.
- Qwen prefill capacity recovery classifies typed Machine Learning framework for Apple silicon errors from direct execution and Rust bounded expert loading. Both paths restore the request checkpoint before a request can be rejected.
- Normal worker builds include direct-mlx. The supervisor resolves user configuration and sends worker-owned startup paths over typed IPC. The inference worker starts without a model directory and receives a selected directory only through SwapModel.
- ModelFamily classifies Qwen3.5, Laguna, K2 Horizon MoVA, DeepSeek-V4, FLUX.2 Klein, and ModernBERT. Discovery advertises executable Qwen, Laguna, K2 Horizon MoVA, the exact pinned Apache-2.0 FLUX.2 Klein 4B profile, and 8-bit affine ModernBERT embedding artifacts; DeepSeek-V4 remains absent from `/v1/models`. FLUX discovery stops at the Diffusers pipeline root and the worker independently rereads exact identity, revision, license, and component evidence before loading. Runtime routing, status, and attribution use canonical `FLUX.2-klein-4B`; immutable artifact provenance retains provider identity `black-forest-labs/FLUX.2-klein-4B`. ModernBERT discovery requires tokenizer plus weights and only the reviewed 8-bit affine profile; other widths stay undiscoverable.
- FLUX.2 Klein supports text-to-image only: BF16 weights, four denoising steps, guidance 1.0, dimensions 64–1,024 in multiples of 16, and one lossless RGB PNG. Rotary position encoding uses adjacent real/imaginary pairs. Euler updates accumulate in FP32 before returning to BF16. Production requires complete VAE decoding because independent tiles cannot preserve global GroupNorm and middle-attention arithmetic.
- Laguna owns strict artifact/text contracts plus descriptor-driven attention, sparse-expert residency and paging, deterministic prompt chunking, persistent prompt caching, and generation under `crates/model-serving/src/laguna/`. Its root chat template may be embedded in `tokenizer_config.json` or supplied by standalone `chat_template.jinja`; a nonempty standalone file beside an embedded root must be selected by that root as an include or the artifact is conflicting. Family-owned shallow discovery requires bounded text sidecars, supported parser/template metadata, a safe complete nonzero shard index, a nonzero context, and an immutable revision before public listing and routing use the same discovered-model snapshot. Its direct-MLX complete-model oracle deliberately uses explicit masks, chronological cache arrays, stable router sorting, explicitly selected expert matrices, and dequantized dense references so production causal attention, rotating caches, partial routing, gathered expert kernels, and packed affine execution cannot validate themselves through identical wiring. Request-start admission reserves rotating temporary workspace for one executable prompt chunk, not the complete prompt. The output parser fail-opens any closed envelope with a usable name; catch-all WARNs the original parser error and forwarded JSON. Unclosed envelopes and tool-call resource bounds salvage at generation end or when a bound is crossed; they never abort the stream. Omitted `torch_dtype` on published MLX affine Laguna artifacts defaults to bfloat16. Laguna decode samples on GPU; omitted artifact `top_k` executes 20 because REST/IPC carry only temperature, top_p, and seed.
- K2 Horizon MoVA owns discovery plus serving under `crates/model-serving/src/k2_horizon_mova/`: strict stacked-affine artifact validation (4-bit group-64 experts, per-module profiles), dense and MoVA layers, an IFM chat renderer with unclosed-think promotion and tool-call salvage, a REST-default thinking budget, chunked prefill with per-chunk progress deltas, a persistent SSD prompt cache whose on-disk format stays bfloat16, an append-only KV slab, and engine-side decode/prefill attribution. Two measured experimental levers stay merged-in but default-off behind `chunking.experimental_quantized_kv_cache_enabled` and `chunking.experimental_fused_moe_decode_enabled`; both measured slower than the bfloat16 gathered baseline (issue #424) and hermetic default tests pin them off. The single-token fused kernels route through the kernel-capability probe family `FusedQuantizedExpertDecode` and fail closed. The long-context 40 tok/s decode bar at ~13k accumulated context remains an open backlog item.
- Laguna preserves native and two-level-compressed NVFP4 artifact descriptions, but loaded linear execution currently binds only native floating-point and affine quantized weights. Runtime-integration directly checks MLX NVFP4 primitives; that primitive coverage does not make a Laguna NVFP4 artifact executable.
- model_family_runtime owns concrete autoregressive families. The inference-worker factory alone selects an autoregressive runtime, FLUX image runtime, or ModernBERT embedding runtime; EngineBackedWorker owns tagged loaded-runtime variants without fake token methods on image or embedding engines. Embedding methods currently live on the image executor trait so `ApplicationState` keeps one executor object.
- model_directories entries in the standard Astronomical configuration are recursive scan roots, not guaranteed leaf model directories. Ignored model acceptance and measurement tests must resolve an exact model ID through Astronomical discovery and must not fall back to an external model-manager directory.
- Qwen3_5MoEArtifactValidator discovers executable model shards and optional vision files from the index, accepts missing MTP-only files for target-only serving, validates optional OptiQ metadata when present, ignores unrelated files, and does not full-hash model payloads.
- Qwen3.5 artifact storage dtype is independent from its configured activation dtype. Config-derived model and vision tensor profiles accept and retain MLX-supported FP16, BF16, or FP32 storage, while affine scales and biases independently accept those types. Resident arrays and sparse expert pages preserve each source dtype; gathered MLX and paged Metal kernels apply the corresponding common output type without widening retained storage.
- Dense model_type qwen3_5 checkpoints use the dedicated qwen3_5 public boundary and execute dense SwiGLU without router or expert allocation. Shallow discovery uses indexed physical visual weights, while loaded-worker image capability requires a complete validated embedded or separate vision tower; an embedded tower may share language shards or occupy a vision-only model shard. Metadata alone remains text-only.
- OptiQ metadata accepts the same affine widths as MLX (2, 3, 4, 5, 6, and 8 bits). Embedding and output-head measurements are optional, but must match config when present. Qwen expert paging resolves native versus affine storage per projection from the module profile and shard inventory, not the model-wide AffineQuantized flag.
- The worker process RSS sampler, hardcoded launch-memory envelope, and heartbeat watchdog layers are gone. Model loading has a 60-second timeout; cancellation acknowledgement has a separate 60-second bound because one large MLX prefill chunk can legitimately outlive the 3-second process-shutdown grace period.
- The inference worker resolves one positive machine MLX memory ceiling at startup. A positive iogpu.wired_limit_mb value is used directly; zero resolves the macOS default once through MLX device information. The value controls MLX allocation guidance and request admission. Production deliberately does not call MLX set_wired_limit: per-buffer residency-set removal under allocation pressure can panic IOGPU on macOS 26.5.2. maximum_mlx_memory_gb is an optional decimal-SI user ceiling in config.json. A live change uses PUT /v1/config/maximum-mlx-memory; an active generation queues only the newest valid cap and applies it before the next request. An idle Qwen increase installs the native and centralized Rust ceilings, then atomically promotes complete experts when the replacement projection fits; a structural promotion failure restores both prior limits. A decrease considers resident request headroom as well as idle active bytes and completes demotion and reclamation before acknowledgement. Status exposes machine, effective, minimum, configured, pending, error, and resulting expert ownership. A worker rejection preserves persisted configured intent and the prior effective runtime value rather than attempting a non-atomic file rollback that could overwrite an external editor. Active and allocator-cache limits form one process-global pair; replacement engines must receive the exact applied pair because a live increase can leave the cache cap below the active ceiling. Request completion and cancellation clear reclaimable allocator state. Replacement-model loading also clears the process-global allocator pool after the prior model is dropped and before replacement weights load. Missing or malformed sysctl output fails startup. Hourly file diagnostics use a 1,024-line lossy queue so slow storage cannot grow memory or stall inference.
- The macOS menu keeps successful maximum-model-RAM feedback visible until status confirms the requested effective ceiling with no pending update, then clears it after one second. Queued applications remain visible until they take effect, and late worker rejections become failure feedback. Public status progress is a token-or-step union: text uses processed/total tokens, while image generation uses completed/total steps. Worker-applied model policy is a strict autoregressive-or-FLUX tagged union whose complete Rust response fixtures are consumed by Swift journey tests; malformed policy becomes a bounded visible polling diagnostic and later valid status self-recovers. Status refreshes execute serially so stale requests cannot replace newer menu state. Swift menu contracts must decode every variant because one invalid object otherwise hides the complete status document.
- The macOS menu embeds Sparkle 2 through Swift Package Manager. Signed daily update checks default on, while downloads and installations remain user-driven; users may opt out or select Stable, Release Candidate, or Development eligibility. Stable distribution signs every code object inside-out with Developer ID Application, preserves Sparkle entitlements, enables Hardened Runtime and secure timestamps, builds a Finder-laid-out drag-to-Applications DMG, notarizes and staples it, then generates the Sparkle signature over those final bytes. The private Sparkle key and Apple credentials belong only in the operator's Keychain and recovery material. Preparation writes an immutable manifest; publication consumes that exact directory, verifies the GitHub asset digest, and only then stages `site/appcast.xml` for Pages activation.
- Stable installation, disk-image creation, Finder layout, signing, notarization, Sparkle acceptance, and GitHub publication live only under `scripts/release/`. Ordinary `scripts/verify-before-commit.sh` must never invoke that namespace; `scripts/test-commit-release-isolation.sh` guards the boundary. Run release contracts explicitly through `scripts/release/tests/test-release-contracts.sh`.
- The explicit scripts/test-mlx-memory-contracts.sh layer runs native MLX allocator contracts, direct Rust MLX-C contracts, and the required large sparse MoE e2e fixture drop-and-reload lifecycle in serial isolated processes. It waits five seconds for Metal after model teardown before native allocation checks. The pinned native allocator rejects any new, reused, or host-backed allocation that would cross the configured ceiling plus one percent without changing active or peak counters. MLX allocator policy is process-global, so do not combine its tests with parallel GPU acceptance. Completed model load can retain tiny graph bookkeeping, so compare cache relationally there; request-finalization cleanup must report zero cache with live model residency.
- Per-prefill-chunk cleanup must synchronize the model-owned MLX graphics-processor stream first. Clear reclaimable allocator cache only at or above 256,000,000 bytes. Request finalization still always clears. The Metal allocator releases cached buffers without synchronizing submitted evaluation or direct Metal input/output work.
- The native MLX build uses runtime Metal kernel compilation so capable Apple GPUs receive Metal 4 matrix kernels; first-use compilation is cold-start work and later processes reuse the system cache.
- bindgen's own crate must resolve the same `syn` major version as its `prettyplease` dependency: bindgen 0.73 failed to compile (E0277, `syn::file::File: ParseQuote`) because the lockfile gave bindgen syn 3 while prettyplease stayed on syn 2 (issue #635, merged with the prettyplease 0.3.0 pin). When a future bindgen bump moves syn again, run `cargo update -p prettyplease` to the matching syn generation in the same change; a bare dependabot bindgen bump alone will fail the hermetic verification.
- Context limits are two-tier since #638: the configured `limits.maximum_context_tokens` is advisory (advertised unchanged; crossing it only logs a warning) and the model artifact's native position count is the only hard rejection boundary. The split lives in `qwen3_5/text/context_token_validation.rs`, each family's text processor, and the engine's `hard_maximum_position_count`.
- MLX 0.32.x rounds the MLX_SDPA_BLOCKS environment variable up to a multiple of 32 and validates the single-pass sdpa_vector threadgroup size against the pipeline limit (both landed in v0.32.1). Before these fixes, a non-multiple-of-32 block count silently corrupted two-pass decode attention by dropping tail softmax partials, and a register-limited one-pass pipeline silently returned all zeros because the Metal driver dropped the dispatch. Current supported model geometries do not hit either broken path; the fixes ensure that future large-head-dimension models fail loudly instead of producing silent wrong output.
- macOS can reject a linker-signed nested bundle executable even when static bundle verification passes. The app assembler signs known leaf code before containers: local builds use ad-hoc signatures, while Stable distribution requires Developer ID Application with Hardened Runtime and timestamping. Do not replace the explicit Sparkle inventory with `codesign --deep` signing.
- The SwiftPM menu executable must enter through a SwiftUI App with @NSApplicationDelegateAdaptor. Marking the NSApplicationDelegate class itself as @main compiles and leaves a process running, but its launch callbacks do not run in the packaged app, so no status item or owned daemon appears. Keep regular activation until the status item registers, then switch to accessory mode on the next main-loop turn.
- UI values labeled GB use decimal SI units (1 GB = 1,000,000,000 bytes). Binary values must use the explicit GiB label; do not use ByteCountFormatter.CountStyle.memory, which applies binary scaling while producing labels such as GB.
- Configuration schema version 1 groups instance runtime, prompt cache, global chunking, per-model policy, and diagnostics in one strict JSON document. The adjacent offline schema is byte-identical to `site/schemas/config/v1/astronomical-config.schema.json`, whose immutable public ID is `https://aosama.github.io/astronomical/schemas/config/v1/astronomical-config.schema.json`. Global chunking supplies independent resident and SSD-paged defaults; per-model chunking overrides only named fields. Per-model generation defaults yield to explicit request values. Dormant model overrides remain unmatched without blocking discovered models; missing speculative-prefill relationships remain configured but unavailable. Resolved configuration generations bind document intent to discovered artifact revisions and effective worker policy. Compatible target-owned MTP tensors are selected automatically from the target shard inventory or its declared target-relative `mlx_lm_extra_tensors.mtp_file` sidecar, with optional per-model depth; standalone MTP artifacts are intentionally not selectable. Legacy unversioned files migrate once without a compatibility execution path; successful migration first preserves exact source bytes in the one-time adjacent `config.legacy-v0.json`, while unsafe migration leaves the source untouched and creates no backup.
- The optional Qwen `thinking.md` seed is default-off behind `runtime.experimental_qwen_thinking_channel_seed_enabled`. Enabled Qwen requests read the instance-scoped file asynchronously and per request; non-Qwen requests and disabled instances do not touch it.
- Resident multi-token prefill uses `prefill_graph_submission_layer_interval` (default 0: one lazy tape). SSD-paged prefill uses `experimental_ssd_paging_prefill_graph_submission_layer_interval` (default 1). One-token resident generation stays at interval 0; SSD decode uses `experimental_ssd_paging_generation_graph_submission_layer_interval`. The two prefill intervals are independent.
- Prompt-processing chunk sizing is deterministic. Resident prefill uses `fixed_prompt_processing_chunk_size_tokens`; SSD-paged prefill uses the required `fixed_ssd_streaming_prompt_processing_chunk_size_tokens`. After memory pressure, Qwen halves the attempted size. Affine model weights accept the MLX-supported 2-, 3-, 4-, 5-, 6-, and 8-bit widths with group sizes 32, 64, or 128. The pinned MLX split-K patch caps row-count influence after 64 row tiles so equivalent 2,048-token and 4,096-token quantized projections retain one reduction topology. Mixture-of-experts assignments are sorted at 64 or more assignments before gathered quantized matrix multiplication. Compatible complete-resident gate/up rows are concatenated one layer at a time during promotion, then execute as one gathered projection plus down; admission reserves the largest one-layer fusion transient. Detach selected lazy expert tensors from their SafeTensors result maps before that loop because the maps otherwise retain every evaluated gate/up source. Paged execution remains unfused. A custom Metal weighted-sum kernel consumes sorted outputs directly instead of restoring the expanded row.
- Deterministic Qwen prompt processing uses the configured fixed chunk size, bounded by remaining prompt tokens and proven memory capacity. After memory-pressure reduction, the sizer halves the attempted chunk. Resident remainders stay exact. Paged prefill folds a trailing stub smaller than one configured chunk into the current forward so a leftover complete-layer SSD sweep is not paid twice.
- Prompt-processing chunk sizing has explicit ownership: `qwen3_5/inference_execution/prompt_processing_chunk_sizer.rs` owns the Qwen deterministic planner and capacity fallback, with configuration beneath `prompt_processing_chunk_sizer/`. Laguna owns its own deterministic planner in `laguna/prompt_processing_chunk_sizer/sizer.rs`. The retired optimizer, persistence, measurement, planning, and IPC modules have been removed.
- The model retains shapeless MLX-C compilations for mixture-of-experts SwiGLU plus multi-token prefill-only attention gating, precise gated normalization, gated-delta decay, and sparse/shared expert combination. Shapeless callbacks must use scalar broadcast constants rather than input-shaped constants, which freeze the first traced token shape. One-token decode deliberately keeps the prior paths. The sorted-expert weighted-sum and gated-delta Metal kernel owners are retained with the model. mlx_closure_new() returning a null context is the valid pre-compilation output placeholder, not an allocation failure.
- Neutral rotating attention retains one-token key/value state in physical ring order because unmasked decode is invariant to a shared key/value permutation. Multi-token updates expose chronological `window + chunk - 1` views for causal masking, then commit only the final window. Do not add a decode-time ring reorder.

## Conventions

- Use CARGO_BUILD_JOBS="$(sysctl -n hw.logicalcpu)" for non-trivial Cargo verification on macOS.
- Classify tests by the highest external dependency needed to prove their contract: hermetic, rest_api, direct_mlx, mlx_memory_contract, serving_acceptance, prompt_cache_acceptance, performance_measurement, macos_menu_contract, native_metal_contract, memory_management_acceptance, or structural_guard. Do not create a new test binary only to express a semantic category; preserve the existing execution boundary when it is the more expensive dependency. Memory-management acceptance uses installed models and proves runtime memory behavior.
- Run routine hermetic, REST, and commit verification through Cargo aliases on one stable target. Commit verification compiles both required Rust boundaries once and then executes them once with live attributed progress. Run named model, memory, and performance journeys through `scripts/run-disposable-cargo-journey.sh`; use `--list` to discover the accepted names. Direct MLX scripts use disposable targets with live progress and individual 120-second guards.
- Run `scripts/test-cargo-artifact-lifecycle-contract.sh` and `scripts/test-cargo-artifact-cleanup-signal-contract.sh` after changing Cargo profiles, aliases, disposable-lane ownership, native output cleanup, or release build target resolution.
- Preview retired native output with `scripts/clean-retired-cargo-native-output.sh --dry-run`; remove it with `--apply` only after reviewing the attributed candidate count and bytes. Run `scripts/test-retired-cargo-native-output-cleanup.sh` after changing its ownership contract.
- Reclaim accumulated stale target artifacts with `scripts/clean-cargo-target-artifacts.sh`; run without arguments for a size report, add `--apply` to clean. It preserves `target/acceptance-evidence` and leaves sccache and native build caches untouched.
- Cargo aliases select only the stable hermetic and REST application programming interface (API) boundaries. The disposable journey dispatcher selects slow and ignored serving-acceptance, prompt-cache, performance-measurement, and parity targets explicitly.
- Keep production Rust sources at or below the 500-line principle; move a cohesive owner to a direct sibling instead of enlarging a near-limit file.
- The tracked Git pre-commit hook checks staged human-authored Rust, Python, shell, Swift, C-family, Metal, JavaScript, and TypeScript source including tests. It blocks files above 600 lines, reads the index rather than the worktree, and exempts only an explicit first-line generated marker. Run scripts/install-git-hooks.sh after cloning to activate it. The separate scripts/check-source-size.sh production-Rust scan warns at 501–550 lines and fails at 551+; run scripts/test-source-size-check.sh to verify both guards.
- Do not add crates, facades, registries, launchers, managers, actors, adapters, or services unless they remove code from the active path.
- Open Brain provenance is project-scoped: every Astronomical recall and structured memory write must declare project_id as astronomical. Store only durable decisions, verified evidence, explicit user preferences, unresolved blockers, and outcome summaries; do not store file inventories, transient test output, local-machine details, or completed implementation logs. Project-scoped recall can include unscoped legacy thoughts, so use only records whose returned project ID is astronomical unless separately verified. Before broad memory cleanup, confirm the candidate records belong to Astronomical.
- Every pull request must identify exactly one existing same-repository issue under `## Linked issue`. The trusted-default-branch `pull_request_target` workflow publishes the required `PR issue compliance` check against the pull-request head without executing pull-request-authored code. Issue state and body format are deliberately outside this provenance check. The checker parses the section with an anchored regex: between the `## Linked issue` heading and the next `##` heading the section must contain exactly one bare reference line (`Fixes #N`, `Closes #N`, `Resolves #N`, or `Refs #N`) and nothing else — any prose inside the section fails the check, so place explanatory text under a separate `## Summary` heading.
- Monitor pull-request checks only with `gh pr checks <number> --watch --interval 5` — never Python or custom polling loops. A command window cannot exceed 120 seconds, and a bounded 10-minute verification can outlive one window; the correct response is to re-invoke the same watch command until it reports terminal states, not a homemade monitor. Body edits re-trigger the compliance check; a stale failing badge can persist on the checks view until the newest run replaces its conclusion.
- Run commands so their output streams live to the terminal; never redirect to a log file and grep it afterward, which leaves the user with silent output. This includes `scripts/verify-before-commit.sh` (~90 seconds, comfortably inside the 120-second window, so no redirect is ever needed) and cargo/test invocations. Only genuinely long background runs (notarization, GPU journeys) may use `nohup ... &`, and their polling must print fresh lines rather than hide them.
- Structured memory lives in Open Brain with `project_id: astronomical` for durable cross-cutting knowledge, and in this guide plus `docs/performance-optimizations-lessons.md` for repo workflow and codebase-procedure lessons — Open Brain's write guardian rejects codebase-specific procedure documentation as ephemeral, so route those here instead of retrying the write.
- Markdown docs should not hard-wrap prose.
- Memory-policy changes are incomplete without the telemetry that proves their effect and the journey assertions that consume it (issue #510). Every memory quantity a user-facing surface shows must be readable by acceptance journeys from engine evidence, and any published memory decomposition must close: named owners plus the unexplained residual plus the owner overrun reconstruct the whole, with a non-zero residual or overrun failing or flagging rather than disappearing.

Pages are read by visitors, so text sizes have a floor: `apps/supervisor/tests/hermetic/site_readability.rs` fails on any declared `font-size` under 0.75rem (12px) or any rule that rescales the root, and the narrow-screen header and footer rows wrap rather than widen the page.
- docs/expert-paging-cpu-gpu-ssd-execution-flow.md - verified map of Rust bounded expert streaming, ordinary Machine Learning framework for Apple silicon gathered projections, and SafeTensors source reads. Update it whenever those boundaries change.
- docs/qwen4-exp-architecture.md - measured evidence for the planned qwen4_exp family (Qwen 3.8 Flash): geometry, the cross-variant packaging matrix, the pinned n-gram lookup and stream-mixing rules, licensing rulings, and the mechanism-owner placement decision. The family is documented but not executable: no `ModelFamily` variant exists yet, so do not treat its artifacts as loadable.
- apps/supervisor/ - localhost astronomicald, Axum REST/SSE, one WorkerHandle, one shared chat/image/embeddings FIFO, one concrete worker loop, and one WorkerProcess. `src/library/` owns catalog, durable download controls, publication, and discovery refresh; `src/supervisor_performance_attribution.rs` owns supervisor operation records. Image and embeddings request, event, and endpoint owners remain separate from chat streaming while sharing model swap, cancellation, containment, memory controls, and status. The embedded Astronomical Observatory serves named deep links including `/library`; GET /v1/system/telemetry exposes local GPU utilization and nullable macOS memory pressure.

- apps/astronomical-menu/ - standalone Swift Package menu-bar application (macOS 14 deployment target). Its bundle identity injects the expected channel, endpoint, state directory, version, and commit. It owns only that instance's bundled astronomicald, consumes the enriched /v1/status document, and renders the Astronomical-specific Orbital Telemetry popover. Build/test it with Swift Package Manager, not Cargo.
- crates/config/ - strict standard-user configuration loader used by the daemon and supervisor resolver; workers receive resolved startup settings through IPC. Its `model_discovery/` owns artifact and family classification (`classify_model_directory`, `ModelFamily`, `discover_classified_model_artifacts`, `ModelCapabilities`), so discovery classification lives here alongside configuration, not only in the supervisor `library/` or model-serving.
- crates/rest-contract/ - public OpenAI-compatible REST/SSE DTOs.
- crates/ipc-protocol/ - bounded supervisor/worker command and event DTOs.
- crates/model-serving/ - artifact_validation/ and safetensors/ own bounded shared artifact reads. memory/ owns cross-component MLX policy. qwen3_5/ and laguna/ own autoregressive families; shared GPU sampling is `gpu_token_sampling.rs` and seed resolution is `sampling_seed.rs`. flux2_klein/ owns exact profile validation, Qwen conditioning, flow scheduling, transformer execution, complete VAE decoding, PNG encoding, memory admission, cancellation, and attribution. modernbert/ owns the 8-bit affine embedding forward pass, content-token mean pooling, and L2 normalization. EngineBackedWorker owns tagged autoregressive/image/embeddings runtimes.
- `crates/runtime-integration/` — unsafe/native MLX C production boundary (via CMake/C++), compatibility-keyed native build store, compiled closure ownership, bounded SafeTensors reader support, ahead-of-time Metal library validation. Native expert cache, native page-store, MLX-C expert cache bindings, MLX paged-buffer-store, and all associated C++ source/headers/tests absent following the centralized memory policy refactor. Its experimental aligned loader compiled only by `experimental-aligned-expert-packs` feature. Native patches pass through `apply_patch_if_needed.cmake`; only MLX source archives are SHA-256-verified.
- registry/download_catalog.json - validated release-authored model catalog; production intentionally permits an empty entries array.
- experimental/aligned-expert-packs/ - non-production research package. It is a workspace member but not a default member and is never bundled in Astronomical.app. Its streaming-model preparer publishes standalone converted revisions into the configured models tree, where ordinary discovery treats them as first-class model identities.
- Integration test roots by execution boundary: hermetic_tests.rs (model-serving, supervisor, runtime-integration, inference-worker), rest_api_tests.rs (supervisor), direct_mlx_tests.rs (model-serving), mlx_memory_contract_tests.rs (model-serving), memory_management_acceptance_tests.rs (inference-worker), prompt_cache_acceptance_tests.rs (model-serving, inference-worker), serving_acceptance_tests.rs (inference-worker), performance_measurement_tests.rs (inference-worker). ## Entry points

- Inspect the machine GPU wired-memory ceiling: sysctl -n iogpu.wired_limit_mb.
- Format: cargo fmt --all.
- Fast hermetic tests: cargo test-hermetic.
- Public REST/API tests: cargo test-rest-api.
- Direct MLX contracts: scripts/test-direct-mlx.sh.
- Explicit MLX memory-contract acceptance: scripts/test-mlx-memory-contracts.sh (requires both named local checkpoints and fails if either is absent).
- Production Rust source-size guard: scripts/check-source-size.sh; structural guard test: scripts/test-source-size-check.sh.
- Install the tracked staged-source pre-commit guard: scripts/install-git-hooks.sh.
- Prepare a notarized macOS release with `scripts/release/prepare-and-publish.sh --tag vX.Y.Z --notes-file PATH --signing-identity NAME --team-id ID --notary-profile NAME`. Preparation keeps `caffeinate` active for its process lifetime because an idle screen lock makes Data Protection Keychain profiles inaccessible; a deliberate manual lock still requires unlocking and retrying. Review the exact prepared directory, then repeat only the tag and output directory with `--publish`; the manifest authenticates the DMG, appcast, and copied notes. Publication requires the remote tag to resolve to the prepared commit, repairs an interrupted matching draft upload, rejects prereleases and conflicting state, and stages the Pages appcast only after the remote DMG digest matches.
- Prove the complete Sparkle trust and installation path with `scripts/release/accept-sparkle-update.sh`; it uses a fictional app under `target/`, a loopback-only feed, the Keychain signing identity, and a 120-second bound to prove signed install/relaunch, external-state preservation, and corrupted-archive rejection without touching Stable or GitHub.
- Model-artifact acceptance: configure `model_directories` in `~/.astronomical-dev/config.json`, set `ASTRONOMICAL_FLUX2_KLEIN_REFERENCE_BUNDLE` to the reference-bundle JSON path, then run `scripts/run-disposable-cargo-journey.sh accept-serving`.
- Real-model model-weight streaming: configure `model_directories`, stop other Astronomical processes, run `scripts/run-disposable-cargo-journey.sh accept-model-ssd-streaming`. Focused journeys use `measure-model-ssd-streaming-*` namespace. After stop, copies `performance.jsonl` and `performance-attribution.jsonl` to `target/acceptance-evidence/...` (or `$ASTRONOMICAL_ACCEPTANCE_EVIDENCE_DIRECTORY`), because disposable targets are deleted.
- Deployment REST liveness: `accept-tool-call-reuse` runs four public TCP requests on one process: long Chat with tools, short Chat, reused long Chat, reused long Responses. Requires clean SSE completion and ready worker afterward.
- Qwen thinking seed: `accept-thinking-seed` selects smallest validated Qwen3.5 artifact, enables isolated runtime experiment, authors `thinking.md`, requires exact text to lead reasoning on streaming Chat Completions and Responses.
- Hard thinking-budget REST: `accept-hard-thinking-budget` streams one bounded Romeo and Juliet request through Chat Completions TCP surface, requires complete model-owned transition, subsequent visible content, and exact forced-token attribution.
- Structured-output REST: `accept-structured-output` loads discovered `Qwen3.5-2B-4bit`, requires Chat Completions and Responses JSON plus HTTP Warning that grammar is not enforced. Embeddings REST: `accept-embeddings` loads `nomicai-modernbert-embed-base-8bit`, requires float, array order, base64, truncated dimensions, and Romeo-versus-finance semantic ordering.
- Model-switch journeys: `accept-laguna-family-swap` exercises Qwen → Laguna XS → Qwen. `accept-cached-reverse-model-swap` exercises large Ornith → small Ornith → cached return under physical-read and latency bounds.
- Speculative-prefill REST: `accept-speculative-prefill` selects smallest validated Qwen artifact as both target and compatible drafter, exercises cold tool journey through config, worker, persistent cache, and public REST boundaries.
- Model-weight streaming support: `scripts/run-disposable-cargo-journey.sh test-model-ssd-streaming-support`; slow measurements run one command at a time through the same dispatcher with `measure-model-ssd-streaming-summary`, `measure-model-ssd-streaming-cold-prefill-50k`, or one `measure-model-ssd-streaming-prefill-*` chunk cell. Prompt-cache performance support and measurements retain their separate persistent-prompt-cache names.

- Experimental one-layer: `measure-experimental-aligned-expert-packs-*-` (generation/prompt-processing/data-plane). Requires explicit GPU approval.
- Inspect one already-downloaded research model without mutation: cargo run -p astronomical-experimental-aligned-expert-packs --bin astronomical-experimental-aligned-expert-pack-preparer -- --model-directory PATH --dry-run.

Acceptance for the converted identity runs through the ignored serving-acceptance journeys `serving_acceptance::aligned_expert_packs::{advertise,chat}` via scripts/run-bounded-cargo-test.sh (serial, 120-second test timeout, memory-capped isolated Development home).
- Experimental native Metal input/output contracts: experimental/aligned-expert-packs/scripts/test-experimental-native-metal-loader.sh contracts. This requires explicit GPU approval before execution.

Build with `scripts/build-development-app.sh`, launch with `open "target/astronomical-macos-development.noindex/Astronomical Development.app"`.
