# Repo Discovery Guide for Astronomical

Agent orientation map for non-obvious repository facts; this is not user-facing documentation or a changelog.

## Maintenance mandate

Read this guide before substantive work and spot-check 2-3 key facts. Update it when paths, entry points, conventions, or expensive gotchas change. Treat it as suspect when Last verified is more than 90 days old.

Last verified: 2026-08-28 (spot-checked: Laguna published MLX affine packaging, closed tool-call fail-open)

## Project overview

Astronomical is an Apple Silicon local model server. The active architecture is a localhost Rust HTTP/SSE process plus one Rust worker subprocess; the worker owns MLX, artifact validation, model state, and chat or image generation. Only one model is resident in GPU memory at a time; the supervisor hot-swaps to a different discovered model when a request changes identity or modality.

## Known gotchas

- Stable uses `~/.astronomical`, port 6732, and an explicitly promoted `~/Applications/Astronomical.app`. Development uses `~/.astronomical-dev`, port 6733, and `Astronomical Development.app`. Direct repository daemon execution and ordinary app builds default to Development. Config, logs, cache, ownership, lock, bundle identity, endpoint, and process cleanup remain instance-scoped; standard endpoints derive from the channel and are not user configuration. Model directories may be shared read-only. Never restore global process-name termination. Separate state cannot isolate shared GPU, wired memory, or SSD bandwidth, so real-model qualification remains explicit and requires an exact model identifier advertised by Development.
- Tests and qualification tools must never load the active Stable configuration or derive writable paths beneath `~/.astronomical`. Read model locations and policy from Development, and keep mutable qualification state in temporary `.astronomical-dev` directories. `scripts/check-test-channel-isolation.sh` enforces this boundary.
- Product version comes from the Cargo workspace. App bundles, `astronomicald --version`, `/v1/status`, the menu, and Observatory expose semantic version, channel, build number, short commit, and dirty state. Stable packaging renders a timeless, badge-free `Astronomical.icns` and rejects dirty worktrees; Development uses the same product artwork with a restrained `DEV` badge and records dirty state.
- The local API supports POST /v1/chat/completions for OpenAI chat chunks, POST /v1/responses for Copilot-compatible response items, and POST /v1/images/generations for one lossless base64 PNG. Chat and Responses share the autoregressive worker command; image generation has a separate typed command and state machine.
- Models are loaded lazily: menu-app startup launches an idle worker with no resident model. The supervisor discovers configured models for /v1/models, canonicalizes supported provider-prefixed IDs, then sends SwapModel only when the first (or a different) REST generation request targets a discovered model. It waits for ModelSwapped before forwarding generation. Process-scoped telemetry and configuration events can precede that acknowledgement and must pass through the shared typed event handler; generation-scoped events remain protocol violations. A rejected model load leaves the worker idle or preserves the previous model so a later valid request can proceed.
- Every instance automatically scans `<instance-state>/models` before user-configured recursive roots. An absent automatic root is an empty Library and is not created during resolution. Effective roots preserve automatic-then-authored order and deduplicate exact lexically equal paths, while `ResolvedRuntimeConfig.configured_model_directories` retains only user-authored roots. A Library model wins over the same public identity in an authored root. Ambiguous identities among authored roots are excluded while unrelated models remain available; bounded status diagnostics identify the model and one-based configuration entries without exposing paths. Existing organization/model trees are discoverable; hidden `.incomplete` staging remains undiscoverable.
- `registry/download_catalog.json` is an immutable release-authored catalog embedded into astronomicald and validated before listener binding. Catalog metadata is bounded to 1,000,000 bytes, 1,024 entries, and 256 bytes per display name. Schema version 1 accepts executable Qwen3.5, Laguna, and FLUX.2 Klein entries with safe public Hugging Face identities, immutable lowercase 40-character hexadecimal revisions, JavaScript-safe byte sizes, optional bounded executable-path selections, and no unknown fields or case-insensitive collisions. `GET /v1/library/catalog` serves authored order and live readiness without worker dependency. Observatory `/library` retries interrupted catalog loads, renders decimal SI sizes, and controls one daemon-owned download.
- One durable Library transfer uses `<instance-state>/models/.download-job.json`; independent store instances serialize mutations through `.download-job.lock`, and partial files remain under `.incomplete/organization/model/`. Job metadata is bounded, strict, atomically replaced, and reconciled from synchronized regular-file lengths after restart. Manifest preflight derives both disk checks from this models volume and persists only release-selected executable files with exact provider digests. Payload transfer streams one immutable file range at a time; quarter-second user-interface progress stays in memory so synchronized job rewrites do not throttle the network path. File completion, pause, failure, verification, and publication remain durable boundaries. Provider SHA-256 or Git-blob SHA-1 evidence is verified before staging is atomically renamed. Publication writes strict provider identity and immutable revision provenance so ordinary discovery preserves readiness after daemon restart. A pre-existing destination is adopted only when every selected file matches provider digest evidence; mismatches remain untouched. A checksum failure truncates only the invalid file so Resume re-fetches it while retaining verified progress. Interrupted preflight, manifest, transfer, and verification states recover as paused. Cancel removes only validated hidden staging and the job document. After rename, readiness remains publishing until discovery refresh succeeds, and restart retries that refresh.
- `/v1/models` publishes maximum input and output token counts as independent capabilities under one shared context window. The maximum input reserves one generation position; request admission enforces the selected prompt plus output budget. Never reject metadata merely because the two independent maxima cannot be used simultaneously.
- Chat and image requests share one serial bounded FIFO queue and one active-request permit. Up to GENERATION_QUEUE_DEPTH requests can wait; excess requests receive HTTP 429 with server_capacity. Queue permits are released immediately when a queued request is cancelled or its HTTP client disconnects.
- XPC code and packaging are deleted. The daemon discovers its sibling inference worker automatically.
- Packaged apps load `mlx.metallib` from `Contents/Resources/share/mlx/`. `~/Library/Caches/Astronomical/native-builds` is the compile-time native store only; a cache wipe must not prevent a shipped app from starting.
- The supervisor must not depend on model-serving or runtime-integration; MLX belongs only in the worker.
- IPC uses one length-delimited JSON frame per command or event with a 32 MiB cap matching HTTP transport. Image bytes remain vectors internally and use base64 on the JSON wire. Oversized chat or image commands fail request-scoped without discarding the loaded worker. Image completion remains private until a separate finalization event proves request-array release and allocator cleanup.
- Chat text validation has no smaller per-message or aggregate-content cap in REST or IPC. The HTTP chat body has a 32 MiB transport cap.
- Qwen3.5 prompt admission, execution, and sampling read vocabulary and context limits from validated config. Initial admission projects resident experts with no routed-page reserve; if context does not fit, it demotes the whole expert owner and reprojects with the model-derived largest routed top-K page. There is no fixed expert-paging headroom field. After an allocation-free persistent prompt-cache lookup, mutable admission also reserves one restored-prefix key/value payload because reconstruction temporarily owns both loaded blocks and concatenated live state; it demotes complete resident experts before reading arrays when that overlap does not fit. Restoration drops loaded block owners before allocator cleanup, then re-admits only the context remaining after the restored prefix. Per-forward admission enforces exact persistent growth plus learned transient peak evidence. A second equal recovery window remains diagnostic and cannot preemptively demote or reclaim experts; typed allocation pressure restores the checkpoint, reclaims the exact deficit, and retries the unchanged chunk.
- Current OpenCode MCP schemas use both type: ["string", "null"] and two-branch nullable anyOf, including constrained integer branches. Copilot CLI also uses two-branch non-null anyOf such as string-or-array paths, plus interactive canvas tools whose input property intentionally has no type; the Qwen3.5 output parser dynamically parses those supported unions and truly untyped properties. Closed `<tool_call>` envelopes fail open: unknown names, sloppy inner XML, and schema mismatches forward to the harness. Resource bounds and unclosed envelopes stay fatal. Do not restore Qwen undeclared-function model-visible correction injection; `ModelVisibleCorrection` remains only as leftover renderer/test machinery. Thinking-enabled generation begins after a prompt-owned <think> prefix, so its parser must start in reasoning state rather than waiting for the model to repeat that marker.
- Copilot CLI 1.0.73 discards text from valid bring-your-own-key response.reasoning_text.delta events and records only an opaque reasoning item ID, producing blank reasoning entries in its interface. For practical Copilot and industry compatibility, Astronomical exposes raw Qwen3.5 reasoning as plaintext summary_text through response.reasoning_summary_text.delta/done and completed reasoning summaries. It never emits plaintext as encrypted_content.
- Public stream failures retain four stable, bounded codes: chat_invalid_request, chat_engine_busy, chat_malformed_model_output, and chat_worker_unavailable. A pre-stream model rejection returns model_load_failed with the worker's cause chain instead of misreporting whole-worker unavailability. Keep human messages actionable without exposing native errors or local paths.
- OpenAI completion IDs carry a process-instance namespace before the request counter so tool-call IDs remain distinct across daemon restarts. Historical tool-call IDs are lifecycle-scoped: reuse is valid only after the earlier call has a result, while unresolved duplicates still fail validation.
- InferenceEngineError::InvalidRequest is request-scoped at generation start, token advancement, and injected-token advancement: emit WorkerEvent::Failed and keep the loaded worker reusable. Truly fatal worker returns use a bounded Tokio runtime shutdown because Tokio standard-input reads cannot be cancelled and must not leave a half-dead process retaining MLX memory.
- Qwen prefill capacity recovery classifies typed Machine Learning framework for Apple silicon errors from direct execution and Rust bounded expert loading. Both paths restore the request checkpoint before a request can be rejected.
- Normal worker builds include direct-mlx. The supervisor resolves user configuration and sends worker-owned startup paths over typed IPC. The inference worker starts without a model directory and receives a selected directory only through SwapModel.
- ModelFamily classifies Qwen3.5, Laguna, DeepSeek-V4, and FLUX.2 Klein. Discovery advertises executable Qwen, Laguna, and the exact pinned Apache-2.0 FLUX.2 Klein 4B profile; DeepSeek-V4 remains absent from `/v1/models`. FLUX discovery stops at the Diffusers pipeline root and the worker independently rereads exact identity, revision, license, and component evidence before loading. Runtime routing, status, and attribution use canonical `FLUX.2-klein-4B`; immutable artifact provenance retains provider identity `black-forest-labs/FLUX.2-klein-4B`.
- FLUX.2 Klein supports text-to-image only: BF16 weights, four denoising steps, guidance 1.0, dimensions 64–1,024 in multiples of 16, and one lossless RGB PNG. Rotary position encoding uses adjacent real/imaginary pairs. Euler updates accumulate in FP32 before returning to BF16. Production requires complete VAE decoding because independent tiles cannot preserve global GroupNorm and middle-attention arithmetic.
- Laguna owns strict artifact/text contracts plus descriptor-driven attention, sparse-expert residency and paging, deterministic prompt chunking, persistent prompt caching, and generation under `crates/model-serving/src/laguna/`. Its root chat template may be embedded in `tokenizer_config.json` or supplied by standalone `chat_template.jinja`; a nonempty standalone file beside an embedded root must be selected by that root as an include or the artifact is conflicting. Family-owned shallow discovery requires bounded text sidecars, supported parser/template metadata, a safe complete nonzero shard index, a nonzero context, and an immutable revision before public listing and routing use the same discovered-model snapshot. Its direct-MLX complete-model oracle deliberately uses explicit masks, chronological cache arrays, stable router sorting, explicitly selected expert matrices, and dequantized dense references so production causal attention, rotating caches, partial routing, gathered expert kernels, and packed affine execution cannot validate themselves through identical wiring. Request-start admission reserves rotating temporary workspace for one executable prompt chunk, not the complete prompt. The output parser fail-opens any closed envelope with a usable name; catch-all WARNs the original parser error and forwarded JSON. Unclosed envelopes stay incomplete. Omitted `torch_dtype` on published MLX affine Laguna artifacts defaults to bfloat16. Laguna decode samples on GPU; omitted artifact `top_k` executes 20 because REST/IPC carry only temperature, top_p, and seed.
- Laguna preserves native and two-level-compressed NVFP4 artifact descriptions, but loaded linear execution currently binds only native floating-point and affine quantized weights. Runtime-integration directly qualifies MLX NVFP4 primitives; that primitive coverage does not make a Laguna NVFP4 artifact executable.
- model_family_runtime owns concrete autoregressive families. The inference-worker factory alone selects an autoregressive runtime or FLUX image runtime; EngineBackedWorker owns tagged loaded-runtime and active-request variants without fake token methods on image engines.
- model_directories entries in the standard Astronomical configuration are recursive scan roots, not guaranteed leaf model directories. Ignored model qualification and measurement tests must resolve an exact model ID through Astronomical discovery and must not fall back to an external model-manager directory.
- Qwen3_5MoEArtifactValidator discovers executable model shards and optional vision files from the index, accepts missing MTP-only files for target-only serving, validates optional OptiQ metadata when present, ignores unrelated files, and does not full-hash model payloads.
- Qwen3.5 artifact storage dtype is independent from its configured activation dtype. Config-derived model and vision tensor profiles accept and retain MLX-supported FP16, BF16, or FP32 storage, while affine scales and biases independently accept those types. Resident arrays and sparse expert pages preserve each source dtype; gathered MLX and paged Metal kernels apply the corresponding common output type without widening retained storage.
- Dense model_type qwen3_5 checkpoints use the dedicated qwen3_5 public boundary and execute dense SwiGLU without router or expert allocation. Shallow discovery uses indexed physical visual weights, while loaded-worker image capability requires a complete validated embedded or separate vision tower; an embedded tower may share language shards or occupy a vision-only model shard. Metadata alone remains text-only.
- OptiQ metadata accepts the same affine widths as MLX (2, 3, 4, 5, 6, and 8 bits). Embedding and output-head measurements are optional, but must match config when present. Qwen expert paging resolves native versus affine storage per projection from the module profile and shard inventory, not the model-wide AffineQuantized flag.
- The worker process RSS sampler, hardcoded launch-memory envelope, and heartbeat watchdog layers are gone. Model loading has a 60-second timeout; cancellation acknowledgement has a separate 60-second bound because one large MLX prefill chunk can legitimately outlive the 3-second process-shutdown grace period.
- The inference worker resolves one positive machine MLX memory ceiling at startup. A positive iogpu.wired_limit_mb value is used directly; zero resolves the macOS default once through MLX device information. The value controls MLX allocation guidance and request admission. Production deliberately does not call MLX set_wired_limit: per-buffer residency-set removal under allocation pressure can panic IOGPU on macOS 26.5.2. maximum_mlx_memory_gb is an optional decimal-SI user ceiling in config.json. A live change uses PUT /v1/config/maximum-mlx-memory; an active generation queues only the newest valid cap and applies it before the next request. An idle Qwen increase installs the native and centralized Rust ceilings, then atomically promotes complete experts when the replacement projection fits; a structural promotion failure restores both prior limits. A decrease considers resident request headroom as well as idle active bytes and completes demotion and reclamation before acknowledgement. Status exposes machine, effective, minimum, configured, pending, error, and resulting expert ownership. A worker rejection preserves persisted configured intent and the prior effective runtime value rather than attempting a non-atomic file rollback that could overwrite an external editor. Active and allocator-cache limits form one process-global pair; replacement engines must receive the exact applied pair because a live increase can leave the cache cap below the active ceiling. Request completion and cancellation clear reclaimable allocator state. Replacement-model loading also clears the process-global allocator pool after the prior model is dropped and before replacement weights load. Missing or malformed sysctl output fails startup. Hourly file diagnostics use a 1,024-line lossy queue so slow storage cannot grow memory or stall inference.
- The macOS menu keeps successful maximum-model-RAM feedback visible until status confirms the requested effective ceiling with no pending update, then clears it after one second. Queued applications remain visible until they take effect, and late worker rejections become failure feedback. Public status progress is a token-or-step union: text uses processed/total tokens, while image generation uses completed/total steps. Worker-applied model policy is a strict autoregressive-or-FLUX tagged union whose complete Rust response fixtures are consumed by Swift journey tests; malformed policy becomes a bounded visible polling diagnostic and later valid status self-recovers. Status refreshes execute serially so stale requests cannot replace newer menu state. Swift menu contracts must decode every variant because one invalid object otherwise hides the complete status document.
- The macOS menu embeds Sparkle 2 through Swift Package Manager. Signed daily update checks default on, while downloads and installations remain user-driven; users may opt out or select Stable, Release Candidate, or Development eligibility. Stable distribution signs every code object inside-out with Developer ID Application, preserves Sparkle entitlements, enables Hardened Runtime and secure timestamps, builds a Finder-laid-out drag-to-Applications DMG, notarizes and staples it, then generates the Sparkle signature over those final bytes. The private Sparkle key and Apple credentials belong only in the operator's Keychain and recovery material. Preparation writes an immutable manifest; publication consumes that exact directory, verifies the GitHub asset digest, and only then stages `site/appcast.xml` for Pages activation.
- Stable installation, disk-image creation, Finder layout, signing, notarization, Sparkle qualification, and GitHub publication live only under `scripts/release/`. Ordinary `scripts/verify-before-commit.sh` must never invoke that namespace; `scripts/test-commit-release-isolation.sh` guards the boundary. Run release contracts explicitly through `scripts/release/tests/test-release-contracts.sh`.
- The explicit scripts/test-mlx-memory-contracts.sh layer runs native MLX allocator contracts, direct Rust MLX-C contracts, and the required Ornith 1.5 35B A3B oQ6e drop-and-reload lifecycle in serial isolated processes. It waits five seconds for Metal after model teardown before native allocation checks. The pinned native allocator rejects any new, reused, or host-backed allocation that would cross the configured ceiling plus one percent without changing active or peak counters. MLX allocator policy is process-global, so do not combine its tests with parallel GPU qualification. Completed model load can retain tiny graph bookkeeping, so compare cache relationally there; request-finalization cleanup must report zero cache with live model residency.
- Per-prefill-chunk cleanup must synchronize the model-owned MLX graphics-processor stream first. Clear reclaimable allocator cache only at or above 256,000,000 bytes. Request finalization still always clears. The Metal allocator releases cached buffers without synchronizing submitted evaluation or direct Metal input/output work.
- The native MLX build uses runtime Metal kernel compilation so capable Apple GPUs receive Metal 4 matrix kernels; first-use compilation is cold-start work and later processes reuse the system cache.
- MLX v0.32.1 rounds the MLX_SDPA_BLOCKS environment variable up to a multiple of 32 and validates the single-pass sdpa_vector threadgroup size against the pipeline limit. Before these fixes, a non-multiple-of-32 block count silently corrupted two-pass decode attention by dropping tail softmax partials, and a register-limited one-pass pipeline silently returned all zeros because the Metal driver dropped the dispatch. Current supported model geometries do not hit either broken path; the fixes ensure that future large-head-dimension models fail loudly instead of producing silent wrong output.
- macOS can reject a linker-signed nested bundle executable even when static bundle verification passes. The app assembler signs known leaf code before containers: local builds use ad-hoc signatures, while Stable distribution requires Developer ID Application with Hardened Runtime and timestamping. Do not replace the explicit Sparkle inventory with `codesign --deep` signing.
- The SwiftPM menu executable must enter through a SwiftUI App with @NSApplicationDelegateAdaptor. Marking the NSApplicationDelegate class itself as @main compiles and leaves a process running, but its launch callbacks do not run in the packaged app, so no status item or owned daemon appears. Keep regular activation until the status item registers, then switch to accessory mode on the next main-loop turn.
- UI values labeled GB use decimal SI units (1 GB = 1,000,000,000 bytes). Binary values must use the explicit GiB label; do not use ByteCountFormatter.CountStyle.memory, which applies binary scaling while producing labels such as GB.
- Configuration schema version 1 groups instance runtime, prompt cache, global chunking, per-model policy, and diagnostics in one strict JSON document. The adjacent offline schema is byte-identical to `site/schemas/config/v1/astronomical-config.schema.json`, whose immutable public ID is `https://aosama.github.io/astronomical/schemas/config/v1/astronomical-config.schema.json`. Global chunking supplies independent resident and SSD-paged defaults; per-model chunking overrides only named fields. Per-model generation defaults yield to explicit request values. Dormant model overrides remain unmatched without blocking discovered models; missing speculative-prefill relationships remain configured but unavailable. Resolved configuration generations bind document intent to discovered artifact revisions and effective worker policy. Compatible target-owned MTP tensors are selected automatically from the target shard inventory or its declared target-relative `mlx_lm_extra_tensors.mtp_file` sidecar, with optional per-model depth; standalone MTP artifacts are intentionally not selectable. Legacy unversioned files migrate once without a compatibility execution path; successful migration first preserves exact source bytes in the one-time adjacent `config.legacy-v0.json`, while unsafe migration leaves the source untouched and creates no backup.
- The optional Qwen `thinking.md` seed is default-off behind `runtime.experimental_qwen_thinking_channel_seed_enabled`. Enabled Qwen requests read the instance-scoped file asynchronously and per request; non-Qwen requests and disabled instances do not touch it.
- Resident multi-token prefill uses `prefill_graph_submission_layer_interval` (default 0: one lazy tape). SSD-paged prefill uses `experimental_ssd_paging_prefill_graph_submission_layer_interval` (default 1). One-token resident generation stays at interval 0; SSD decode uses `experimental_ssd_paging_generation_graph_submission_layer_interval`. The two prefill intervals are independent.
- Prompt-processing chunk sizing is deterministic. Resident prefill uses `fixed_prompt_processing_chunk_size_tokens`; SSD-paged prefill uses the required `fixed_ssd_streaming_prompt_processing_chunk_size_tokens`. After memory pressure, Qwen halves the attempted size. Affine model weights accept the MLX-supported 2-, 3-, 4-, 5-, 6-, and 8-bit widths with group sizes 32, 64, or 128. The pinned MLX split-K patch caps row-count influence after 64 row tiles so equivalent 2,048-token and 4,096-token quantized projections retain one reduction topology. Mixture-of-experts assignments are sorted at 64 or more assignments before gathered quantized matrix multiplication. Compatible complete-resident gate/up rows are concatenated one layer at a time during promotion, then execute as one gathered projection plus down; admission reserves the largest one-layer fusion transient. Detach selected lazy expert tensors from their SafeTensors result maps before that loop because the maps otherwise retain every evaluated gate/up source. Paged execution remains unfused. A custom Metal weighted-sum kernel consumes sorted outputs directly instead of restoring the expanded row.
- Deterministic Qwen prompt processing uses the configured fixed chunk size, bounded by remaining prompt tokens and proven memory capacity. After memory-pressure reduction, the sizer halves the attempted chunk. Resident remainders stay exact. Paged prefill folds a trailing stub smaller than one configured chunk into the current forward so a leftover complete-layer SSD sweep is not paid twice.
- Prompt-processing chunk sizing has explicit ownership: `qwen3_5/inference_execution/prompt_processing_chunk_sizer.rs` owns the Qwen deterministic planner and capacity fallback, with configuration beneath `prompt_processing_chunk_sizer/`. Laguna owns its own deterministic planner in `laguna/prompt_processing_chunk_sizer/sizer.rs`. The retired optimizer, persistence, measurement, planning, and IPC modules have been removed.
- The model retains shapeless MLX-C compilations for mixture-of-experts SwiGLU plus multi-token prefill-only attention gating, precise gated normalization, gated-delta decay, and sparse/shared expert combination. Shapeless callbacks must use scalar broadcast constants rather than input-shaped constants, which freeze the first traced token shape. One-token decode deliberately keeps the prior paths. The sorted-expert weighted-sum and gated-delta Metal kernel owners are retained with the model. mlx_closure_new() returning a null context is the valid pre-compilation output placeholder, not an allocation failure.
- Neutral rotating attention retains one-token key/value state in physical ring order because unmasked decode is invariant to a shared key/value permutation. Multi-token updates expose chronological `window + chunk - 1` views for causal masking, then commit only the final window. Do not add a decode-time ring reorder.
- Sparse mixture-of-experts ownership and streaming are Rust-owned. Phase-aware residency preserves a stable complete-layer foundation for multi-token prefill and uses remaining capacity for routed decode-page overlays selected from observed demand. Multi-token cold layers stream one complete-layer bounded SafeTensors page; one-token misses stream only the routed experts required by that forward.
- Forward admission and live-ceiling changes reclaim routed decode overlays before complete prefill layers. Mandatory reads may promote the page just loaded when typed admission allows it; generation preparation only plans optional decode topology and never performs eager source reads. Planning failure clears the optional decode plan and continues through bounded streaming.
- The retired C++ expert page store, paged-execution kernels, C application binary interface, Rust wrappers, MLX paged-buffer patches, indirect-resource patches, and native tests are absent from the build. Do not restore them without a representative end-to-end result exceeding the Rust path with exact parity and no memory regression.
- Multi-token nonresident layers stream as complete operation-local pages. One-token nonresident layers load temporary routed top-K pages. There is no production multi-token expert-group streaming path and no whole-forward missing-route replay. `/v1/status` reports `paged` with near-zero Experts payload for pure streaming, and `resident` only when the complete expert model is resident. Model-core plus transient request work is the expected idle/active MLX split for large paged models.
- The menu derives cumulative session prompt reuse from completed-request prompt and reused-token totals; those totals survive model swaps and reset with the supervisor process. Its stacked MLX memory snapshot reconciles tracked expert, model-core, and request-context payload against measured active memory, assigns the remainder to runtime work, and derives available bytes from the machine-specific MLX ceiling. Request-scoped SpecPrefill draft scoring instead reports one standalone live-only Drafter category that includes its temporary decoder context and remaining draft-phase active work; it returns to zero after release. MLX has no allocator ownership tags, so never present the tracked categories as independently measured physical allocations or assign process-wide allocator-cache and peak counters to one model.
- Native expert slots use aligned MLX-owned storage because packed UInt32 safetensors payloads can begin at offsets unsuitable for typed mapped arrays. Product-neutral MLX core range reads copy exact byte intervals into committed slots before typed views are created.
- Bounded expert reads use exact SafeTensors source intervals and generic positional file-read attribution. The generic descriptor reader separately retains same-reader serialization because representative warm model loading regressed under concurrent host reads. The pinned MLX generic input/output pool uses half the logical processors clamped to 4–8 workers.
- Production ExpertPager constructs Rust bounded-read manifests from standard SafeTensors and never discovers `.astronomical-aligned-expert-packs`, even when generated research files remain beside a model.
- experimental/aligned-expert-packs owns the research format, explicit preparer, feature-gated Metal input/output loader, hermetic contracts, native contracts, and three ignored one-layer data-plane qualifications. Its measurements cover an isolated load-to-gather-quantized-matrix-multiplication boundary and are not production-serving evidence.
- The pinned MLX 0.32.1 `Event` stores a non-owning pointer when `set_error(Error&)` is used. The experimental Metal input/output loader publishes its owned error before host-signalling a failed shared event, immediately commits the public stream wait with an asynchronous retirement owner, and retains that owner until MLX copies the waited error. Explicit completion includes observer publication. Deterministic failure injection is compiled only by the native contract option.
- Decode keeps sampling on the graphics processor and submits one token ahead with mlx_async_eval. Laguna uses the shared `gpu_token_sampling.rs` categorical path rather than greedy argmax. Forward evaluation includes the sampled output and independently branching convolution state; full-attention storage and fused recurrent sibling output are already reachable graph roots. Each actual prefill chunk is one gated-delta dispatch. Fixed prompt size, full-attention key-value growth, experimental solid-state-drive paging graph-submission intervals, speculative-draft forward length, and prompt-cache boundaries come from the nested `chunking` configuration. Those experimental intervals are ignored while experts are fully resident. Do not restore a second recurrent-only chunk size, hidden model-serving defaults, per-token host sampling, or key-value concatenation.
- Real process/MLX/HTTP Qwen3.5 and FLUX qualification is isolated behind the model-artifact-qualification inference-worker feature and ignored tests. FLUX qualification resolves the exact pinned model through Development discovery, uses a Romeo and Juliet-derived prompt, and never falls back to external model-manager paths. Its independent reference bundle binds exact reviewed provider and Diffusers source revisions, model revision, complete generation controls, prompt digest, the MLX 0.32.1 bfloat16 keyed-noise layout and Float32 digest, decoded RGB bytes, and bundle-bounded maximum and mean channel tolerances. The qualification implementation independently enforces 99th- and 99.9th-percentile channel limits; native repetition remains a separate assertion.
- Ignored model-weight streaming measurements are collected under `apps/inference-worker/tests/model_ssd_streaming/` across the existing performance, memory-acceptance, and model-artifact execution boundaries. Resident execution is the comparison control. Persistent prompt-cache measurements remain under `performance_measurement/` because they measure cached decoder-state storage rather than model-weight streaming.
- Four in-process prompt-processing chunk sweeps (1,024/2,048/4,096/8,192 tokens) share the same feature gate and are ignored by default; they inject a `Qwen3_5PromptProcessingChunkSizer` through the configured-worker test override over duplex pipes rather than spawning a subprocess, so they do not report peak physical footprint.
- Persistent Qwen3.5 prompt caching defaults to enabled and is SSD-backed under the standard Astronomical configuration directory with a default 50 GB global ceiling across every model and revision. When persistent_prompt_cache_enabled is false, the worker does not derive per-model storage paths or contracts, open or scan directories, read or write state, plan capture checkpoints, reserve publication workspace, or collect cache statistics; existing files remain untouched. prompt_cache_max_size_gb controls decimal capacity when enabled. Each model retains an isolated model-and-revision subdirectory via PromptCacheConfig::for_model(). All SSD-backed cache implementation lives under crates/model-serving/src/persistent_cache/. Cache contents are disposable local artifacts with no migration support. Format 12 stores each complete block under blocks/<hash>/ with one manifest and contract-required sequence.safetensors and/or boundary.safetensors files. The manifest binds ancestry and the model storage fingerprint; state-file metadata retains only format, block geometry, and that fingerprint. Model-owned non-token causal input contributes to the block where it enters the prompt and then propagates through ancestry. Global quota scopes topology by namespace and storage fingerprint, removes abandoned transactions before committed content, protects active ancestry, and evicts complete unprotected subtrees rather than individual sequence files. Startup completes eligible parent-boundary compaction before evicting an interrupted over-quota chain. Prefix lookup restores only validated complete topology. Required initialization, restoration, and publication failures remain typed model or request failures.
- Prompt-cache startup cleanup records separate bounded counts and bytes for interrupted-transaction recovery, obsolete formats, corrupt current-format content, and quota eviction. This evidence survives hits and short prompts, attaches to the first zero-restoration structural miss in performance.jsonl, then is consumed once; the physical miss reason remains unchanged.
- Required prompt-cache capture is synchronous and direct: Machine Learning framework for Apple silicon writes each tensor through one retained descriptor, materializing the largest tensor first and releasing it before the next. No complete serialized Rust payload, queue, rate limiter, writer thread, or pending-byte budget exists. Cache-enabled prompt processing clamps each forward to the next block boundary, reserves one largest-tensor publication workspace, synchronizes and clears allocator storage, then atomically renames one staged block directory and synchronizes its parent. Laguna restores append-only state one decoder layer at a time, consumes that layer's tensors from every loaded block, materializes its final key/value pair, and releases source arrays before the next layer; admission reserves one layer source pair rather than a complete-prefix duplicate so cache restore does not demote a fitting resident model. Only durable Published or validated AlreadyPublished advances the request cursor and parent key. Typed active-memory pressure reclaims pageable experts and retries the unchanged captured arrays once; storage, validation, and quota failures do not retry as memory pressure.
- Adaptive RAM growth guarding is always enabled in production configuration. Direct engine construction may still disable it for controlled tests and benchmarks.
- performance_attribution_enabled defaults to false and requires an application restart because supervisor and worker owners share it. Worker-local aggregate reports use `logs/performance-attribution.jsonl`; supervisor-owned startup operations use `logs/supervisor-performance-attribution.jsonl` so independent buffers never append to one file. Disabled supervisor attribution opens no file and reads no clocks. Enabled catalog loading records flushed start/end/outcome evidence before listener binding; writer initialization, append, or flush failure stops startup with a typed cause. Worker aggregate reports distinguish logical source-copy bytes from process-attributed macOS physical disk-read deltas; the latter can include unrelated worker input/output. Bounded per-phase/per-layer SSD source summaries expose repeated reads without storing pass rows or expert identifiers. Event-level route tracing and the provisional cache-policy simulator were removed after the research phase because they added hot-path ownership without establishing a production policy improvement.
- Compatible Qwen MTP stays off unless a model sets `acceleration.mtp.enabled` to true. Optional `mtp_draft_depth` accepts 1–3. Changing either field requires worker replacement. Opted-in depth uses an explicit artifact default when present and otherwise depth one; artifact maximum is compatibility evidence, not performance evidence. A declared maximum clamps an over-request without disabling MTP, while absent maximum metadata leaves an explicit depth uncapped and emits a bounded depth-one-guidance note. Canonical MTP tensor names may differ from stored sidecar names, but every source enters through the validated inventory/source-ID boundary. Malformed, conflicting, or incompatible optional MTPLX metadata keeps optional MTP target-only without affecting target serving, while missing vendor metadata does not block a physically complete known-compatible Qwen inventory. One stored MTP layer is reused autoregressively at resolved fixed depth 1–3. Native greedy text-only execution clamps per request for output, context, thinking, and memory feasibility; sampled, vision, persistent-prompt-cache, SSD-paged sparse experts, feedback-fallback, and quarantined requests remain target-only. Status reports configured, artifact maximum/default, resolved requested, capped, and effective execution depth, runtime state, and bounded resolution or unavailability reasons without per-request fallback mutation. Do not infer capability from model names, shard counts, or local paths.
- Eligible text-only MTP requests run nonterminal prompt chunks through the exact target path without retaining hidden rows or growing private MTP history. The terminal prefill chunk alone captures target hidden rows and initializes private MTP history; the reserved final prompt token is still forwarded once at generation startup as the first draft seed. Terminal capture timing remains attributed, while its distinct memory context prevents cheaper prefix execution from distorting adaptive RAM-growth evidence. Requests remain target-only whenever the persistent prompt cache is available because its snapshots do not contain shifted MTP history.
- Qwen target verification uses a geometry-derived custom quantized projection only for Float16 or BFloat16 affine 4-bit or 5-bit weights whose input width is a multiple of 512 and output width is a multiple of eight. Every unsupported valid geometry repeats one-token MLX quantized projection so verifier arithmetic remains aligned with ordinary decode. Direct MLX qualification compares the specialized route exactly against that token-local reference across the retained dispatch matrix.
- Optional draft-assisted SpecPrefill is disabled by default and remains separate from lossless MTP. The user selects any compatible configured Qwen draft; production has no model-name allowlist. Target and draft compatibility compares canonical token-to-identifier mappings rather than tokenizer file bytes. Vision-capable drafts project their own visual embeddings from shared processed pixel rows because target and draft text widths can differ. Draft lookahead sees the complete prompt. The target fully prefills the leading system-and-tool control span, applies sparse selection only to conversation tokens before the final generation-start token, and retains all image-pad rows. Sparse target tokens remain one compact forward; native dynamic MLX rotary positional embedding preserves original prompt positions by treating selected token rows as one-token batch rows during rotation only. The worker reports disabled, active, or unavailable state plus configured draft identity, validated revision, and a bounded failure reason through Ready, ModelSwapped, WorkerHealthSnapshot, and /v1/status. Configured loading, scoring, selection, nonrecoverable sparse execution, and required persistence failures stop model use or the request without target-only retry. A sparse target MLX capacity rejection remains inside SpecPrefill and reuses ordinary prefill checkpoint restoration, exact expert reclamation, and bounded chunk reduction. Selection metadata and dense draft decoder state persist under the drafter model and revision. Selection-bound target decoder state is captured before the final generation-start token under the target revision, drafter identity, selection policy, prompt prefix, and ordered image digests; an exact repeat restores target state and processes that final token once without loading the drafter. Keep-percentage changes purge only obsolete selections and selection-bound target state for the same pairing. Resident draft payload and its maximum expert page are charged to the same target MLX memory authority.

Scoring admission may demote only when its exact decoder, visual, expert-page, checkpoint, and publication workspace requires capacity. Draft release attempts target promotion before sparse target execution.

- Keep production Rust sources at or below the 500-line principle; move a cohesive owner to a direct sibling instead of enlarging a near-limit file.
