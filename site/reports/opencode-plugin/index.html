The copy-paste problem

A model list pasted into a settings file goes stale.

Without the plugin, OpenCode learns about local models from a configuration block: an address, and the identifier of each model typed in by hand. Download a new model and OpenCode does not know about it until the file is edited again, and the context window it assumes is a default, not the model's.

The plugin asks the running app which models it serves and registers them in OpenCode itself. Chat models appear in /models under Astronomical; picture, speech, embedding and decision models are left out, because OpenCode cannot talk to them.

opencode plugin add opencode-astronomical

Step 2 List and ask

OpenCode listed all 8 chat models the app served, and one of them answered a prompt.

8 of 8 listed

Each model arrives with the context window, reply limit, picture input, reasoning output and tool support the app reports, so OpenCode plans long sessions around the model's real capacity. The list refreshes every 30 seconds; a model added or removed in the app appears or disappears within half a minute, and if the app is not running the models are simply absent rather than shown out of date.

The plugin's 85 tests read the app's own model listing from a file that a Rust test holds to what the app serves, so a renamed field fails the build on whichever side has not followed.

What it sends

Nothing leaves the Mac.

The plugin talks only to the app on this Mac, over loopback, to read the model list and the app's version. It writes one file, a log of what it did that never grows past 1 MB, in OpenCode's own state folder. The package is its TypeScript source, 22 files with no dependencies of its own, published with the repository's Apache-2.0 license.

Works with the launcher

astronomical launch opencode still starts one session on one model without touching OpenCode's settings. Both use the provider name astronomical, so with both in play OpenCode lists each model once.

Limits

What this check does and does not show.

The check ran on one Mac, against a build of the app from source rather than the published app, with OpenCode 2.3.0. The plugin needs OpenCode 2.3 or later. How fast a model answers depends on the model, its size, the memory you allow and whether it is already loaded; the first reply from a model that is not yet loaded can take a while, and the plugin allows ten minutes for it.
